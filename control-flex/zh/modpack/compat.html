模组兼容性

Control Flex 为整合包而生：先自动发现，再按需逐级加码 —— 游戏内适配中心、社区配置库、Compat JSON、桥接模组。

第一层：自动发现

启动时 Control Flex 会扫描 Minecraft 的 KeyMapping 注册表，把每个非原版绑定注册为动态动作。只要模组通过标准方式注册了按键（JEI 配方键、战斗模组技能键、地图快捷键……），就会出现在按键映射中，无需任何配置文件。

库类模组会被自动豁免（内置清单覆盖 Fabric API、Kotlin 语言支持等家族），不会混进可适配列表。

内置兼容配置

模组 JAR 内附带一小撮内置兼容配置，每次启动都会释放到 config/controlflex/compat/default/：

模组 内置了什么
Just Enough Items (JEI) 配方 / 用途查看键位（GUI 层）、一批不需要暴露的内部按键加入忽略清单
Epic Fight 战斗模式相关的键位与界面规则；指向官方桥接模组 cfx-compat-epicfight
Nightfall 该模组的按键与界面适配

其余模组靠自动发现或社区配置库补充；内置配置只在其目标模组实际安装并加载时生效。

第二层：游戏内模组适配中心

打开 Control Flex 设置 → 模组适配：每个已安装模组按名称、图标与版本列出。进入某个模组后有三个页签：

页签 用途
按键绑定 该模组被发现的全部动作；分配层级（Main / Screen / Overlay）并绑手柄按键
界面适配 该模组界面打开时的摇杆模式、层级映射与光标规则
叠层适配 对交互式 HUD（法术轮盘、轮盘菜单、拍照 HUD 等）做同样的事

添加界面 / 叠层规则的方法：先在游戏里打开目标界面一次，让 Control Flex 记录它；然后在模组详情里点 + 添加界面/叠层适配，从“最近页面”（最多 50 条）中选中即可。无法归属到模组的条目可以自动扫描。

每根摇杆在该页面上可以选用不同的行为：

行为 说明
Independent 摇杆方向作为独立动作，在“层级映射”中绑定；Overlay 默认，以及 Screen 右摇杆默认
Radial Path 摇杆描出路径 / 角度 —— 法术轮盘、轮盘菜单类界面
Virtual Mouse 摇杆在该界面内移动光标；Screen 左摇杆默认

没有规则时：Screen 层左摇杆为 Virtual Mouse、右摇杆为 Independent；Overlay 层两杆保持 Independent（即该层的四向绑定）。光标样式可选系统 / 基岩 / 手型；Virtual Mouse 可调光标速度，Radial Path 可调阈值、半径、角度偏置与是否记忆上一次角度。

规则编辑是写时复制：内置与社区文件只读，改动落到 config/controlflex/compat/user/；某个模组的 Reset Config 会恢复到内置或已应用的社区默认。

第三层：社区配置库

官方社区源：ControlFlexMC/cfx-compat-configs。在模组适配里点 Sync Configs，然后浏览变体、预览按键 / 界面 / 叠层内容，确认后 Apply —— 应用前会先备份已有的用户文件。也可以添加自定义远程源，或在模组详情页导入 / 导出本地 JSON。欢迎向该仓库提交新模组的配置 PR。

第四层：Compat JSON（整合包作者与高级用户）

JSON 是这套 UI 背后可分享的载体。把文件放到 config/controlflex/compat/user/{mod_id}.json；桥接模组可以把自己的配置打进 compat/mods/（运行时只读）。一份配置可以做到：

  • 把按键分配到 Main / Screen / Overlay（inGameKeys / screenKeys / overlayKeys）。
  • 为每个按键选择派发通道（KeyMapping、Forge 事件总线、GLFW 兼容轮询、界面输入）。
  • 忽略无用按键（ignoreKeys）、持有指定物品时抑制按键（itemSuppressKeys）、附加提示文案。
  • 声明界面 / 叠层的摇杆映射（Independent / Radial Path / Virtual Mouse，与 UI 中的选项一致）。

示例结构（节选字段，展示按键分层与状态联动）： 

{
  "mod_id": "epicfight",
  "mod_name": "Epic Fight",
  "home_page": "https://www.curseforge.com/minecraft/mc-mods/epic-fight-mod",
  "ignoreKeys": ["key.epicfight.dodge"],
  "inGameKeys": ["epicfight:key.epicfight.attack"],
  "screenKeys": [],
  "overlayKeys": [],
  "itemSuppressKeys": [{
    "item": "mymod:special_weapon",
    "playerState": ["mymod:combat_mode"],
    "suppressActions": ["attack"]
  }]
}

字段全集与取值请以权威字段参考为准：cfx-compat-configs 字段参考（中文） / English。

playerState 条件配合桥接模组推送的状态生效（IPlayerStateRegistry，键名形如 modId:stateName）—— 桥接写法见开发者文档。

模组有自己的输入系统？用桥接模组

如果目标模组绕开 KeyMapping、有运行时的战斗状态、或直接读取手柄，就需要一个使用 IControlFlexPlugin SPI 的桥接模组：它可以导出 compat JSON、推送玩家状态、响应控制器插拔。官方范例是 cfx-compat-epicfight（内置 Epic Fight 配置就指向它）。开发者文档见 API 快速开始。

仍然有问题？按这个顺序排查

  1. 看按键映射 —— 这个动作绑到正确的层了吗（Screen / Overlay / Main）？
  2. 打开该模组的模组适配 —— 添加界面 / 叠层规则，或应用社区配置。
  3. 如果模组只监听物理键，用虚拟键鼠绑定。
  4. 手写或分享一份 compat JSON；模组完全绕开 KeyMapping 时，写一个桥接模组。
