常见问题排查

手柄出问题，先判断是哪一类：库没加载、设备没被识别，还是游戏崩了。下面按症状分诊，点「详情」进对应的处理步骤。

30 秒分诊

完全没有手柄

设置 → 手柄选择是空的，按键没反应。先看库有没有加载，再看设备有没有到 SDL。

库加载失败 →

游戏启动就崩

崩溃报告里有 gamepadjni / UnsatisfiedLinkError，或 Windows 弹窗说发布者无法验证。

启动崩溃 →

手柄能用，但不对

震动、光标、按键映射、模组界面 —— 这类问题不在加载，先查设置与功能页。

常见问题一览

按症状找。表格里没有的，先按上面三张卡片分诊。

症状 可能原因 详情
Windows 弹窗说无法确认 gamepadjni.dll 的发布者，手柄同时失效 智能应用控制拦截了未签名的 DLL 详情 →
日志出现 no usable gamepad backend JNI 和 JNA 两条后端都没能加载 详情 →
UnsatisfiedLinkError，但没有 Application Control 字样 架构不匹配：32 位 x86 的 JVM，或 Windows 上用 ARM64 的 JVM。JAR 只带 x86_64 原生库，所以 Windows on ARM 也要用 x64 版 Java；Android 上则是 ABI 不支持，或启动器 APK 没带 SDL3。 详情 →
no usable gamepad backend，且 JNA: ... not on the classpath 1.7.10（或 classpath 被精简过的启动器）：没有 JNA 可以回退。 详情 →
手柄列表是空的，日志里也没有 gamepad-jni 报错 库本身加载正常，是设备没到 SDL：多半被别的程序占着（Steam Input、DS4Windows、远程串流），或者蓝牙配对失效、线只能充电。 详情 →
Steam 里手柄正常，游戏里完全不认 Steam Input 接管了设备 详情 →
启动即崩溃，崩溃报告里出现 gamepadjni 原生库加载失败，或模组冲突 详情 →
按键能用，但没有震动 手柄没有马达、电量太低，或者当前连接方式会丢掉震动（部分第三方手柄走蓝牙时如此）。 详情 →
Linux：手柄时有时无 /dev/input 的权限或 udev 规则有问题，或者 Steam Input 先一步占住了设备。 详情 →
Android：游戏能跑，但手柄永远不出现 启动器改写了 os.version，或者 Gamepad Input Mode 还是 Mapped (Virtual Keys)，没切到 SDL Direct。 详情 →
屏幕上有两个光标，或光标位置与点击对不上 启动器的虚拟鼠标指针没关 详情 →
模组按键绑了却没反应 层不对，或缺少该模组的界面 / 叠层规则 详情 →

更细的平台差异见平台支持；加载器、Java 版本或前置装错，见 MC 版本支持。

报告问题时带上这些

  • logs/latest.log 里 [gamepad-jni] 附近的三十行左右 —— 不要只发一张游戏截图。
  • Windows 版本，以及智能应用控制是「打开」「评估」还是「关闭」。
  • Minecraft 版本、加载器，以及准确的 Control Flex 版本号。
  • 手柄型号与连接方式（USB / 蓝牙 / 接收器）。
  • 能找到的话：CodeIntegrity 事件。事件查看器 → 应用程序和服务日志 → Microsoft → Windows → CodeIntegrity → Operational，事件 ID 3077，里面会写明被拦的文件。

在哪看 SAC：Windows 安全中心 → 应用和浏览器控制 → 智能应用控制设置。只有「打开」会拦；「评估」只观察不拦；「关闭」说明你遇到的不是 SAC。
