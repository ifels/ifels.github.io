概念

几个贯穿全站的基础概念：动作与绑定、七层按键架构、界面与叠层、配置放在哪谁生效。先读完这一页，后面每个功能页都会更短。

动作与绑定

  • 动作（Action）：一个可绑定的功能单元 —— jump、use_item、screen_menu_open_1，或 jei:key.jei.showUses 这样的模组键。每个动作归属于一个阶段（游戏内 / 界面），绑定表负责把动作映射到手柄按钮。
  • 绑定（Binding）：动作 + 按钮 + 触发方式（PRESS / HOLD / …，见触发模式）。同一个按钮在不同上下文里可以触发不同动作 —— 这正是分层要解决的问题。
  • 模板与配置：模板自带一整套默认绑定；配置是你在模板之上的修改。两者都在设置与键位里管理。

七层按键架构

一个标准手柄只有十来个输入；一个整合包可能暴露上百个动作。七层模型让同一个按钮在不同上下文里含义不同 —— 按钮当前做什么，取决于哪一层处于激活状态：

层 何时激活
Main 游戏内默认：移动、视角、战斗、快捷栏与日常模组动作
Shift 1–4 按住对应的层切换键时；四个互不影响、完全显式的绑定面
Screen 任意界面打开时：光标、槽位导航、翻页、滚动
Overlay 交互式 HUD 打开时；需显式声明，不继承 Main

完整默认值、编辑规则与常见误区：七层按键架构。

界面（Screen）与叠层（Overlay）

  • Screen（界面）：游戏停止操控的状态 —— 容器、合成、设置、模组自己的界面。打开期间玩家不能移动、不能转视角，输入切到 Screen 层。以 Screen 类的全限定类名标识，例如 net.minecraft.client.gui.screens.inventory.InventoryScreen。
  • Overlay（叠层）：游戏继续进行的状态 —— 打开期间玩家仍可移动、转视角。它可以只是一小块 HUD（法术轮盘、第三方径向菜单、照片 HUD），也可以铺满全屏；关键在于底下的游戏还在运行。以「打开它的一方」的类名声明。
  • 输入行为不同：Screen 层自带完整默认绑定（虚拟光标、槽位、翻页、滚动）；Overlay 层不继承 Main —— 未配置的动作保持安静，HUD 不会误触战斗键。
  • 在 compat JSON 里它们对应 screen / overlay 两段（overlay 段不支持 menus）。见模组适配与 compat JSON 速查。

快速判断：打开后还能走路的就是 Overlay；一打开就不能动的是 Screen。最终以 compat 声明为准。

配置放在哪、谁生效

  • 键位：所有版本线的配置根目录都是 config/controlflex/ —— templates/、profiles/、compat/、radial_menu/、guides/、keyboard/、backup/，布局一致。
  • compat 配置：四层 user > pack > mods > default，越靠上越优先。用户层在 config/controlflex/compat/user/<mod_id>.json，游戏内编辑器写回的也是它。详见 compat 概览。
