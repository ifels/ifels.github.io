功能详解

七层按键架构

标准手柄只有十几个输入，一个整合包却能暴露上百个动作。七层模型让同一个物理按键在不同场景承担不同职责 —— 这是 Control Flex 所有其他功能的地基。

七层一览

层 何时生效 说明
Main 游戏内默认层 移动、视角、战斗、快捷栏与日常模组动作
Shift 1–4 按住对应的层切换键时 四个修饰层，各有一整张绑定表；松开切换键自动回到 Main
Screen 任意界面打开时（背包、箱子、模组 UI、设置） 确认、返回、切页、滚动、槽位跳转与容器操作；打开界面不会和游戏内键位打架
Overlay 交互式 HUD 打开时（法术轮盘、第三方轮盘菜单、拍照 HUD 等） 显式绑定、不继承 Main：未配置的动作保持静默，HUD 不会误触发战斗键

Shift 1–4：完全显式的修饰层

Shift 层是四个独立的绑定平面。理解下面四条规则，就理解了这个功能：

  • 移动 / 视角键默认沿用 Main 的值（模板生成时就填好了），其余动作默认未绑定 —— 也就是“完全显式”。
  • 之后修改 Main 不会同步到 Shift 层；反之亦然。每一层自己说了算。
  • 层切换键固定为 HOLD（Main 层的 layer_shift1–4 四项不可改成其他模式）。
  • 每个 Shift 层自动派生一个“返回 Main”绑定，模式为 RELEASE —— 松开切换键即回到 Main，无需手动配置。

常见误解：Shift 层不是“空槽位实时继承 Main”。运行时不存在回退 —— 空槽就是未绑定。模板只是把移动 / 视角的默认值预先填成和 Main 一样，方便你上手。

Screen 层：界面里的那套键位

只要有任何界面打开，输入就切换到 Screen 层。默认分成四组：

  • 光标：左摇杆驱动虚拟光标（也可用方向绑定做光标导航，两者是独立的绑定项）。
  • 槽位：D-Pad 在格子之间跳转，A 选格，Y 快速移动（Shift+点击），X 取一半。
  • 导航：A 确认、B 返回 / 关闭、LB/RB 切页（创造标签页、配方书页、指南列表等）。
  • 滚动：右摇杆上/下模拟滚轮，左/右轻按切换选项。

Screen 层还能模拟滚轮等物理按键（见虚拟键鼠）；光标行为细节见光标与界面操作。

Overlay 层：交互式 HUD

Overlay 层覆盖游戏仍在进行的状态 —— 法术轮盘、第三方轮盘菜单、拍照 / 附件类 HUD；它们可以只是一小块悬浮物，也可以铺满全屏，但玩家仍能移动和转视角。它的默认值贴近游戏手感（移动、视角、跳跃、攻击、使用、滚动），并以 B 作为返回。两个要点：

  • 不继承 Main：没配置的动作在 Overlay 相位保持静默，避免 HUD 打开时误触发战斗键位。HUD 打开期间层切换也会被抑制。
  • 需要把 HUD 声明为交互式上下文：游戏内在模组适配里为它添加 Overlay 规则；模组作者可以用 Control Flex API 的 IInteractiveContextRegistrar 主动声明（见API 参考）。需要跨界面保持按住的按键可用相位锁定延续到解锁。

层归属在哪里改

  • 按键映射页按层显示与编辑：切换层标签，或直接改某一层的行。
  • 一个动作出现在哪些层，在动作详情页按动作设置；切换模板会把层归属重置为模板默认，而“重置为模板默认设置”不会改变层归属。
  • 点击手柄按键栏捕获输入；捕获中 ESC 取消；右键行可清除、重置或改变层归属。

默认值（Basic 模板）

项 默认
Shift 1 / 2LB / RB（按住）
Shift 3 / 4未绑定 —— 需要时自己指定（背键适合放这里）
Overlay 返回B（点按）
打开设置Back + Start（点按）
