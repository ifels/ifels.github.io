功能

界面菜单

界面菜单（Screen Menu）是一份可绑定的动作列表，能在 Control Flex 认识的任意界面上方弹出 —— 容器、任务书、模组 GUI —— 而不必关掉底下的界面。按一个键打开，选一项执行，就像你亲手在界面里点过一样。需要 Control Flex 0.9+。

它是怎么工作的

  • 五个菜单、五个绑定：screen_menu_open_1 – screen_menu_open_5 是普通的可重绑动作，开箱即有默认键位。
  • 画在界面之上：菜单以列表面板覆盖在当前界面上；打开期间有一层输入遮罩，点击和按键不会漏进底下的界面。
  • 槽位来自适配配置：模组的 compat 条目（或你自己的配置）可以预填菜单动作；不可用的槽位在加载时就被过滤掉。
  • 每槽一个动作：手改 JSON 与游戏内编辑器走同一套校验。

菜单动作从哪来

  • 槽位只能放按键绑定动作：槽位的 actionId 指向一个可重绑的按键动作，写成 modId:key 形式 —— 例如 jei:key.jei.showUses。依赖鼠标悬停的动作（快速移动、取一半）放不进来，因为打开菜单会清空悬停。
  • 键必须在该界面上生效：一个模组键只有在其真正生效的界面上才会被列出、可用 —— 即本模组自己声明的界面加上 addToScreens、减去 removeFromScreens。这也正是编辑器的候选列表；目前没有内建动作可放。
  • 加载期过滤：空白动作、gui_press / inv_select（光标隐藏时无意义）、screen_menu_open_*（菜单里不能套菜单）、非 GUI 层动作、解析不到键位的动作，全部在加载时丢弃，保留原顺序。
  • 可以跨模组引用：菜单里可以引用别的模组的键（比如在原版物品栏菜单里放 JEI 动作）；菜单本身只存在于「拥有这个界面」的模组的 compat 配置里。

在 compat JSON 里添加动作

菜单声明在「拥有该界面」的模组的 compat JSON 的 screen 段里 —— 原版界面挂在 minecraft 名下。两步：先让键在这个界面上生效，再给该界面条目加上 menus 数组。 

{
  "mod_id": "examplemod",
  "mod_versions": [
    {
      "version": "",
      "screenKeys": {
        "key.examplemod.sort": {
          "addToScreens": [
            "net.minecraft.client.gui.screens.inventory.*InventoryScreen"
          ]
        }
      },
      "screen": {
        "com.examplemod.client.gui.ExampleChestScreen": {
          "menus": [
            {
              "id": 1,
              "name": "Quick Actions",
              "translations": { "zh_cn": "快捷操作" },
              "slots": [
                { "actionId": "examplemod:key.examplemod.sort" },
                { "actionId": "jei:key.jei.showUses" }
              ]
            }
          ]
        }
      }
    }
  ]
}

菜单对象字段：

字段 说明
id1–5，必填。编号即打开键 screen_menu_open_N 的身份；重复 id 保留最后一个，越界 id 整条菜单丢弃。
name
translations		显示名；translations 按语言码（zh_cn…）给译文，规则与径向菜单相同。都没有时回落本地化的「菜单 N」。
pos九宫格位置：lt lc lb tc cc bc rt rc rb；默认 cc（居中）。
heightauto（按内容 3–12 行）或固定行数 3–12；越界数值会被夹到范围内。
scale0.5–2.0，按 0.05 取整；默认 1.0。
slots最多 12 条 { "actionId": "..." }；数组顺序即显示顺序；同一动作重复时只保留第一次出现。
  • overlay 段（含 "*" 兜底条目）不支持 menus —— 写了会被丢弃并记录一条警告。
  • 分层：内置 compat 配置打底；用户层 config/controlflex/compat/user/<mod_id>.json 按菜单 id 整项覆盖（写了哪个 id 就替换那个菜单，没写的由内置补齐）。游戏内菜单编辑器保存时写进的也是这个文件。
  • 同一动作出现在多个菜单里完全允许 —— 只在一个菜单内去重。

在设置里编辑

  • 每界面的设置页新增 菜单（Menu） 标签：菜单列表、可拖拽排序的编辑器、名称 / 位置 / 高度 / 缩放，以及实时预览。
  • 重复点击会以 toast 提示，而不是之后悄悄丢掉槽位。
  • 层级映射新增「隐藏未激活动作」：表格只列出当前界面真正能触发的行；重置仍按未过滤的全集执行。
