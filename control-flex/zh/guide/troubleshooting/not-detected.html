手柄未被识别

日志里没有 gamepad-jni 报错，说明库已经加载成功；问题在设备层 —— 系统没认出来、被别的程序抢走，或连接方式不对。

先确认系统认不认

Windows：Win+R 输入 joy.cpl，在「测试」页按几下。这里看不到设备，游戏里也不会有。

macOS：无线手柄看系统设置 → 蓝牙是否已连接；有线手柄看「系统信息 → USB」里有没有出现。

Linux：evtest 或 jstest /dev/input/js0，设备节点要存在且能产生事件。

被别的程序占用

Steam Input、DS4Windows、BetterJoy、远程串流都会先一步接管手柄。被接管后，游戏看到的是虚拟键鼠或另一个虚拟手柄，Control Flex 读不到真实设备。

先把这些程序完全退出（不是最小化），再重启游戏。Steam 里还要在「设置 → 控制器 → Steam 输入」关掉对应手柄的支持。

确认方法：关掉程序后，joy.cpl / evtest 里仍然能看到手柄，才算没被独占。

连接方式

  • USB：用能传数据的线 —— 很多附赠线只能充电。换一个端口，尽量避开 USB Hub。
  • 蓝牙：先在系统里删除配对，再重新配对；配对后按一下手柄的配对键唤醒。
  • 接收器 / 电池：换电池或充电；接收器插主板后置 USB 口，别插前面板。

最后在别的游戏或系统面板里试同一个手柄，确认硬件本身没问题。

Linux：权限与 udev

手柄节点在 /dev/input/event* 和 /dev/input/js*，当前用户要能读。Flatpak / Snap 版启动器还多一层沙箱，需要额外给设备权限。

关掉 Steam，确认当前用户能读事件设备，再用 evtest 或 jstest 看手柄出不出来。

还是不行时，看 ls -l /dev/input/js* 的组权限，或把用户加入 input 组后重新登录。

Android：启动器

Android 上手柄能不能出现，几乎完全取决于启动器：Gamepad Input Mode 必须是 SDL Direct，os.version 也不能被改写成普通内核号。

具体两个设置见平台支持；改完要完全退出游戏再启动。

另外确认启动器有设备权限；部分系统需要在应用设置里允许「附近设备」。

还是不行

日志里搜 gamepad-jni 和 SDL：如果只有加载成功、没有设备行，问题就在这一页；如果出现 UnsatisfiedLinkError，回到库加载失败。

报障时按概览页的清单带上日志和系统信息。
