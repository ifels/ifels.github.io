启动崩溃

先别急着删模组。崩溃报告的第一行通常已经说明是哪一类：原生库、模组冲突，还是 Java / 内存。

先看崩溃报告

报告在实例目录的 crash-reports/。看 Description: 和第一段堆栈就够了，不用从头读。

关键字 说明
UnsatisfiedLinkError
gamepadjni		 原生库没加载成功。SAC、架构、1.7.10 的 JNA 都在库加载失败页。
Mixin apply failed
InvalidInjectionException		 模组注入冲突：某个 mixin 的目标或注入点对不上。按模组兼容页的流程二分排查。
OutOfMemoryError 内存不足。调大启动器的 -Xmx，或减少模组。
UnsupportedClassVersionError Java 版本与 Minecraft 不符，对照 MC 版本支持换 Java。

如果是原生库

报告里出现 gamepadjni、SDL3 或 UnsatisfiedLinkError，先去库加载失败：SAC 拦截、32 位 JVM、Windows on ARM、1.7.10 没有 JNA 都在那里。

如果是模组冲突

搜 Mixin apply failed、InvalidInjectionException 或 [ModCompat]；用二分法禁用一半模组定位，完整流程见模组兼容。

没有崩溃报告就退出

看启动器自己的日志和退出码。常见原因是 32 位 Java、内存不足、Java 版本不对；先确认启动器用的是 64 位 x64 Java。

报障时按概览页的清单带上日志、崩溃报告和系统信息。
