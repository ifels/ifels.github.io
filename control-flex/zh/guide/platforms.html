平台支持

Control Flex 通过 libgamepadjni + SDL3 读取手柄。桌面三平台的原生库与 SDL3 都随 JAR 提供，开箱即用；Android 上 SDL3 必须来自启动器 APK，因此不同启动器的行为并不完全一样。

支持总览

平台 架构 SDL3 来源 状态
Windows x86_64 · ARM64 JAR 内置（SDL3.dll） 支持
macOS x86_64 · Apple Silicon (aarch64) JAR 内置（libSDL3.0.dylib） 支持
Linux x86_64 · aarch64 JAR 内置（libSDL3.so） 支持
Android
启动器里的游戏 JVM		 arm64-v8a · armeabi-v7a · x86_64 启动器 APK 提供，JAR 不打包 支持
iOS — — 尚未支持

平台判定只看 os.version：以 Android- 开头即视为 Android，其余按桌面处理。os.name（Android 启动器同样写 Linux）只用于诊断日志，不参与判定。

桌面平台

  • 无需安装 SDL3、驱动或额外运行库 —— 模组固定使用 JAR 内打包的 SDL3，不与系统里已有的 SDL 冲突，也不会去搜索系统路径。
  • Windows 的 x86_64 与 ARM64 都随包提供原生库（gamepadjni.dll + SDL3.dll）。
  • macOS 同时提供 Intel 与 Apple Silicon 两份 libgamepadjni.dylib，Rosetta 与否都能用。
  • Linux 提供 x86_64 与 aarch64 两份 libgamepadjni.so；Steam Deck 之类的 aarch64 设备同样在列。
  • 手柄热插拔、多手柄识别、按手柄身份（名称 / 类型 / 序列号）记忆配置，在三个桌面平台上行为一致。

Android（启动器环境）

Android 版 Minecraft: Java Edition 由启动器提供的 JVM 运行，手柄链路因此分成两段：SDL3 来自启动器 APK（启动器已经在 ART 侧装好 SDL 的 glue），libgamepadjni.so 由模组自带并按 os.arch 解压加载。两者顺序固定 —— 先 SDL3，再 JNI 桥，否则动态链接器绑不到同一份库。

已验证的启动器

启动器 如何找到启动器的 libSDL3.so
Fold Craft Launcher (FCL) 设置 POJAV_NATIVEDIR 为 APK native 目录，走绝对路径
Zalith Launcher 2 (ZL2) 同上
Mojo Launcher
v3_openjdk		 不设 POJAV_NATIVEDIR；APK native 目录在 LD_LIBRARY_PATH 里，通过 System.loadLibrary("SDL3") 命中
Amethyst Android 设置 POJAV_NATIVEDIR，走绝对路径

这是兼容性说明，不是运行时白名单：只要启动器把 os.version 写成 Android-*，未列出的启动器同样会走 Android 路径。

ABI 与原生库

os.arch JAR 内目录
aarch64 / arm64native/android-arm64-v8a/
arm / armv7l / armv8lnative/android-armeabi-v7a/
x86_64 / amd64native/android-x86_64/
i386 及其他 不支持 —— 初始化失败，游戏仍可正常启动（只是没有手柄）

Android 上的注意事项

不要覆盖 os.version。部分启动器的自定义 JVM 参数或版本 JSON 会把它改成普通内核号（例如 5.0）或干脆不写 Android- 前缀，这时模组会把环境当成桌面 Linux，去加载桌面的 SDL3，结果是手柄在设置里始终不可见。确认启动器注入 -Dos.version=Android-<版本> 没有被你的自定义参数覆盖。

  • JAR 里没有 Android 版 libSDL3.so；不要在 mods 目录旁边再塞一份 SDL3，加载到没有启动器 glue 的 SDL 会让手柄永远不可见。
  • 需要自带 libgamepadjni.so 时，把 CFX_LIB_PATH 指向包含该文件的目录（系统属性优先于环境变量）。
  • Android 上 SDL 与启动器共用同一个进程实例，所以退出游戏时模组不会 SDL_Quit 整个库，避免拆掉启动器的 video / glue。
  • 配置目录仍是 config/controlflex/，相对启动器为实例指定的游戏目录；换启动器（或换实例目录）时，配置不会自动跟过去。
  • 震动、光标、分屏这类功能的实际可用度取决于启动器窗口模型与设备：分屏为桌面多实例场景设计，Android 上一般无法同时跑两个实例。

平台与依赖对照

平台 需要额外安装 配置文件位置
Windows / macOS / Linux 无（SDL3 内置） config/controlflex/
Android 无（SDL3 由启动器提供；启动器需被本页列出的机制覆盖） 启动器实例目录下的 config/controlflex/

排障速查

现象 先检查什么
设置 → 手柄选择里完全没有设备（桌面） JAR 是否与 MC 版本、加载器匹配（见 MC 版本支持）；手柄是否被其他程序（Steam Input、远程串流等）独占
Android 上游戏正常但手柄始终不可见 os.version 是否被覆盖；启动器是否属于已验证的那几种；日志里 POJAV_NATIVEDIR 与 SDL3 路径是否打印出来
日志出现 UnsatisfiedLinkError Android 上是 ABI 不被支持（如 32 位 x86）或启动器 APK 缺 SDL3；桌面上则是原生库与系统架构不符
iOS 设备上找不到入口 iOS 尚未接入（平台层已预留判定位，但没有原生库）
