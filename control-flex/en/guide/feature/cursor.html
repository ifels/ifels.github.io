Features

Cursor & GUI

Once a chest or inventory is open, a pad has to point, click, and drag like a mouse. The Screen layer covers this with three mechanisms: a virtual cursor, slot snapping, and D-Pad slot jumps.

Virtual Cursor

  • How it moves: the left stick's raw axis values are routed through Minecraft's mouse event pipeline — a separate mechanism from the direction bindings (cursor_navi_*).
  • Cursor speed: 2–20 pixels per tick, tuned in Cursor Settings.
  • Cursor style: the system cursor, a Bedrock-style set, or a hand style (textures ship with the cursor style packs).

Slot Snapping

  • On by default, switchable in Cursor Settings.
  • When the stick stops, the cursor snaps to the nearest container slot; the snap distance is adjustable from 1–80 pixels.
  • Only active while holding an item — an empty hand moves the cursor freely without sticking.
  • Hover slowdown: with snapping on, the cursor slows while hovering a slot for precise selection.

D-Pad Slot Navigation

When precision is not needed, the D-Pad jumps between slots directly. It uses cone-shaped targeting, so long horizontal rows and irregular grids (custom containers) still jump reliably. Slot jumps coexist with the virtual cursor — the left stick takes over free movement at any time.

Beyond: Screens That Only Read Physical Keys

Some mod screens ignore the virtual cursor and only react to keyboard/mouse events — use Virtual Keyboard & Mouse to inject real keys there (e.g. map B to physical Esc). To customize stick behavior per screen (Independent / Radial Path / Virtual Mouse), add a Screen rule in Mod Adaptation.
