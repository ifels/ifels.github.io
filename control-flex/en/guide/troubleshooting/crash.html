Crashes on Startup

Do not start deleting mods yet. The first lines of the crash report usually say which class this is: a native library, a mod conflict, or Java and memory.

Read the Crash Report

Reports live in crash-reports/ under the instance folder. Read the Description: line and the first few stack frames — not the whole file.

Keyword What it means
UnsatisfiedLinkError
gamepadjni		 The native library did not load. SAC, architecture and the 1.7.10 JNA step are all on Library Load Failures.
Mixin apply failed
InvalidInjectionException		 A mod conflict: a mixin target or injection point no longer matches. Bisect the mod list as described on Mod Compatibility.
OutOfMemoryError Not enough heap. Raise the launcher's -Xmx, or remove mods.
UnsupportedClassVersionError The Java version does not match the Minecraft version — see Minecraft Versions.

If It Is the Native Library

If the report names gamepadjni, SDL3 or UnsatisfiedLinkError, go to Library Load Failures first: the Smart App Control block, 32-bit JVMs, Windows on ARM and the 1.7.10 JNA step are all covered there.

If It Is a Mod Conflict

Search for Mixin apply failed, InvalidInjectionException or [ModCompat]. Disable half the mods, then half of that half, until the culprit falls out; the full procedure is on Mod Compatibility.

Exits Without a Report

Check the launcher's own log and exit code. The usual causes are a 32-bit Java, too little memory, or the wrong Java version; confirm the launcher is using 64-bit x64 Java first.

When reporting, attach the log, the crash report and system details listed on the overview page.
