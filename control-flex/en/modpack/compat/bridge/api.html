Interface reference

Every public type in com.ifels.controlflex.api: the entry point, the plugin interface, the four providers, the state registry, the overlay and camera hooks, and the asset installer. Each section gives the signature and its calling rules; the snippets are meant to be copied.

Section: Overview · Setup & lifecycle · Interfaces · Implementations · Who uses the API

Type overview

Package com.ifels.controlflex.api, 28 public types in total (13 of them new in 0.9, marked below). Everything except IPlayerStateRegistry.setState() must be called on the client main thread.

Type Purpose
ControlFlexApiStatic entry point: availability check plus provider accessors
IControlFlexPluginSPI plugin interface (lifecycle callbacks)
ICompatAssetInstallerAsset installer (only usable inside the matching callback)
IActionStateProviderQuery whether an action is currently active
IInputProviderController connection state and hardware view
IControllerStateLive view of sticks / triggers / buttons
IControllerCapabilitiesHardware capabilities (type, paddles, gyro, rumble)
ButtonNameButton and axis name constants
IPlayerStateRegistryPush modId:state states for JSON to consume
IInteractiveContextRegistrarDeclare an interactive overlay's foreground / background
ICameraLookConsumerTake over each frame's look delta (when a mod owns the camera)
IScreenHandler · IScreenHandlerRegistryPer-screen handlers: take over the back press and receive HUD visibility pushes (0.9.2.1+)
IActionBindingProvider · IActionBindingInfo · IControllerGlyphResolve which buttons an action is bound to right now, with their glyphs (0.9.2.1+)
IActionRegistrar · ActionRegistration · IControlFlexActionNative action registration: bridges declare actions without KeyMapping (0.9.2.2+)
ActionLayer · ActionTrigger · DefaultBinding · BindingLayerRegistration enums and the default-binding description (0.9.2.x)
HudStateReasonWhy a HUD state was pushed (0.9.2.1+)
ControllerType · InputModeController type / current input mode enums

Input injection was removed in 0.9.0: IInputInjector and getInputInjector() are gone, so tooling that needs synthetic gamepad input has to stay on 0.8.x.

Interfaces added in 0.9 need Control Flex 0.9+ (control-flex-api 0.9.2): the per-screen handlers, binding queries and native action registration below have no implementation on 0.8.x — a true ControlFlexApi.isAvailable() does not mean these providers exist, so null-check after fetching.

ControlFlexApi (static entry point)

boolean isAvailable()               // installed and fully initialized
boolean isControllerConnected()     // a controller is connected

// Providers (null when unavailable)
IActionStateProvider getActionStateProvider()
IInputProvider getInputProvider()
IPlayerStateRegistry getPlayerStateRegistry()
IInteractiveContextRegistrar getInteractiveContextRegistrar()

String getApiVersion()              // e.g. "0.9.2"
void reloadGuides()                 // reload guide configs from disk

IActionStateProvider

boolean isGameActionActive(String actionId)   // game layer (no screen open)
boolean isGuiActionActive(String actionId)    // GUI layer
Set<String> getActiveGameActions()             // live view: never cache across ticks
Set<String> getActiveGuiActions()              // live view: never cache across ticks

Three action ID forms:

  • Built-in actions: attack, use, jump, sneak, move_forward …
  • Vanilla keys: key.jump, key.sneak
  • Mod keys: epicfight:key.epicfight.attack (modId:keyName; the key name carries no modid: prefix)

IInputProvider · IControllerState · ICapabilities

// IInputProvider
boolean isConnected()

IControllerCapabilities getCapabilities()      // null when disconnected
String getGamepadName()                        // null when disconnected
int getGamepadIndex()                          // -1 when disconnected

// IControllerState — live view; sticks -1..1, triggers 0..1, +Y points down
float getLeftStickX()  / getLeftStickY()
float getRightStickX() / getRightStickY()
float getLeftTrigger() / getRightTrigger()
boolean isButtonAPressed() ... isDpadUpPressed() ...
boolean isButtonPressed(String buttonName)     // prefer ButtonName constants
float getAxisValue(String axisName)
boolean isShiftLayerActive()

// IControllerCapabilities
ControllerType getControllerType()   // XBOX / PLAYSTATION / NINTENDO_SWITCH / ...
boolean hasPaddles() / int getPaddleCount()
boolean hasTouchpad() / hasGyro() / hasRumble() / hasAnalogTriggers()
boolean isNintendoLayout()           // A/B swapped

ButtonName gives three groups: buttons (A…Y, DPAD_UP, LEFT_BUMPER, LEFT_TRIGGER, LEFT_STICK_CLICK, BACK, START, GUIDE, PADDLE_1…PADDLE_4, TOUCHPAD), stick directions (LEFT_STICK_UP …) and axes (AXIS_LEFT_X, AXIS_RIGHT_TRIGGER …).

IPlayerStateRegistry

void setState(String stateKey, boolean active)  // thread-safe, callable from any thread
boolean getState(String stateKey)               // client thread
void clearState(String stateKey)                // drop the registration

stateKey is modId:stateName (e.g. epicfight:battle_mode) — exactly the string compat JSON reads in itemSuppressKeys[].playerState.

ICameraLookConsumer (0.8.8+)

boolean consumeLook(float yaw, float pitch)
// true  = this frame's look is consumed: Control Flex must not write player rotation
// false = not consumed: Control Flex keeps its normal path
  • Why: a mod has taken over the rendered camera (Epic Fight's TPS combat camera, lock-on, …), so the player's yRot/xRot is no longer what you see; the look delta has to be handed to that mod.
  • Called at most once per frame; the arguments are deltas calibrated before turning, the same scale the vanilla mouse pipeline hands to the mod that took over.
  • Override cameraLookConsumer() in your plugin and return an implementation; returning null (the default) means no takeover.

IInteractiveContextRegistrar

void notifyOverlayForeground(String className)   // overlay entered the foreground
void notifyOverlayBackground(String className)   // overlay went back (pairs with foreground)
void clearAll()                                  // fallback: world unload / mod shutdown

className is the fully qualified class name — Control Flex looks it up in the compat JSON overlay table to resolve stick and cursor behavior. Null-check first: getInteractiveContextRegistrar() may be null.

IScreenHandler · IScreenHandlerRegistry (0.9.2.1+)

// IScreenHandlerRegistry — one handler per exact screen class
void register(String className, IScreenHandler handler)
boolean isHudVisible(String className)   // diagnostic only: state is pushed, not polled

// IScreenHandler
boolean onBack()        // return true to consume the back press; false falls through to Escape
boolean ownsHud()       // explicit opt-in; a back-only handler is not a HUD owner
boolean onHudState(boolean visible, HudStateReason reason)
// reason: DEFAULT / RESTORED / USER_TOGGLE
// applied=false keeps the stored value at the last good state
// HUD state persists in config/controlflex/screen_hud_state.json

The back press is dispatched only to the focused class. HUD state is pushed on foreground change, on registration while already foreground, and on user toggle — applied first, persisted after, so a failed apply is not stored.

IActionBindingProvider — which button fires this action (0.9.2.1+)

IActionBindingInfo getEffectiveBinding(String actionId)
// resolves against the layer the dispatcher would use,
// including per-screen and per-overlay tables

// IActionBindingInfo
List<? extends IControllerGlyph> glyphs()   // bound buttons + their glyphs
// configured-but-unreachable reads as unbound:
// a hint cannot advertise a button that cannot fire

Alongside it, ICursorController gains warpToGui(x, y): park the virtual pointer on a hand-drawn highlight in GUI coordinates, then activate it with gui_press. A read-only cursor-position peek is exposed for screen-only UIs.

Native action registration — onRegisterActions (0.9.2.2+)

// IControlFlexPlugin — runs before the profile loads, so defaults still apply
default void onRegisterActions(IActionRegistrar registrar)

registrar.register(ActionRegistration.builder()
    .id("mymod:my_action")            // must live in your own namespace
    .displayName("My Action")
    .layers(ActionLayer.SCREEN)       // IN_GAME / SCREEN / OVERLAY; none = all three
    .defaultBinding(new DefaultBinding("button.name", TriggerMode.PRESS))
    .build());

// IControlFlexAction — level handle for hold-style usage;
// ActionTrigger arrives on the activation edge with mode + matching class
  • Registered actions never reach the vanilla controls screen and are never re-attributed by a compat config; getActionIds() and getEffectiveBinding() include them.
  • Screen / Overlay bindings are written to the user_screen_overrides.json table the editor already owns — there is no second store.
  • The registration window opens around discoverPlugins and closes before onControlFlexReady; calling the registrar later throws. Callbacks fire from the event stream, not per-frame dispatch — a HOLD triggers once and releases once.

ICompatAssetInstaller

boolean install(String resourcePath, String fileName)
// resourcePath: classpath path inside your jar, e.g. "/assets/mymod/compat/targetmod_keys.json"
// fileName:     target file name inside compat/mods/ or guides/mods/
// returns:      true when installed
