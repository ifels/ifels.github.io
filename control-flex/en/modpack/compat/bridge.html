When JSON is not enough: bridge mods

Compat JSON can only adjust things that already exist — registered KeyMappings, dispatched keys, opened screens. If a mod ships its own input system, you have to plug in on the Java side. That is a bridge mod.

1. First: do you actually need code?

Compat JSON can Only a bridge mod can
Place registered keys on Main / Screen / Overlay Make keys that never registered a KeyMapping appear in the binding list
Choose the dispatch channel (including the GLFW polling mirror) Reach mods that call GLFW.glfwGetKey directly (the GLFW layer cannot be injected)
Suppress actions by main-hand item plus player state Push the mod's runtime state into Control Flex for use as a condition
Phase persistence, ignored keys, tips, per-screen stick parameters Read stick axes for fully custom logic (vehicle steering, camera)
Fall back to virtual keyboard / mouse for mods that only see physical keys Tell Control Flex "this overlay is in the foreground now" and switch stick behavior

One-line test: if the mod's keys show up under Key Mapping → that mod, you do not need a bridge. If they do not, you do.

2. What control-flex-api is

  • A separate repository, ControlFlexMC/control-flex-api, published through JitPack; currently 0.9.0.
  • It ships Java 8 bytecode and loads on any JVM 8+, so a bridge mod does not have to share the main mod's toolchain.
  • compileOnly only: Control Flex provides it at runtime. Do not bundle the API into your jar.
  • Scope: read controller input, query action states, push mod states, declare interactive overlays, install compat / guide assets.
// build.gradle
repositories { maven { url 'https://jitpack.io' } }

dependencies {
    compileOnly 'com.github.ControlFlexMC:control-flex-api:0.9.0'
    compileOnly 'org.jetbrains:annotations:24.0.1'
}
# mods.toml（Forge / NeoForge）
[[dependencies.your_mod_id]]
    modId = "controlflex"
    mandatory = true
    versionRange = "[0.8.7,)"
    ordering = "AFTER"
    side = "CLIENT"

# fabric.mod.json
{ "depends": { "controlflex": ">=0.8.7" } }

The first line is always an availability check — Control Flex may not be installed, and SDL3 may have failed to initialize. Every provider can be null. 

if (!ControlFlexApi.isAvailable()) {
    return;   // fall back: skip every controller-related path
}

3. Plugin skeleton: IControlFlexPlugin

Callback When it runs / what it is for
getModId() Plugin identifier, used for logging and de-duplication.
onInstallCompatConfigs() Called before ready; use installer.install() to install compat JSON into compat/mods/.
onInstallGuideAssets() Same idea, into guides/mods/.
onControlFlexReady() The single initialization callback; every provider is ready at this point.
onControllerConnectionChanged() Fires when a controller connects or disconnects.
requireApiVersion() Default method that checks the minimum API version and returns false when unmet. 
package com.example.mymod;

import com.ifels.controlflex.api.*;

public class MyPlugin implements IControlFlexPlugin {

    @Override
    public String getModId() { return "my_bridge_mod"; }

    @Override
    public void onInstallCompatConfigs(ICompatAssetInstaller installer) {
        installer.install("/assets/my_bridge_mod/compat/targetmod.json", "targetmod.json");
    }

    @Override
    public void onControlFlexReady() {
        if (!requireApiVersion("0.8.7")) return;
        if (!ControlFlexApi.isAvailable()) return;

        ControlFlexApi.getPlayerStateRegistry().setState("mymod:initialized", true);
    }
}

Registration goes through an SPI services file; Control Flex discovers plugins automatically: 

src/main/resources/META-INF/services/com.ifels.controlflex.api.IControlFlexPlugin

com.example.mymod.MyPlugin

Installed JSON lands in compat/mods/: above default/, below user/ — so players can still override your defaults instead of being locked in.

4. What you can reach

Interface Use
IInputProvider · IControllerState Read stick axes, triggers and buttons. IControllerState is a live view — caching it across ticks gives you stale values.
IControllerCapabilities Controller hardware capabilities (model, rumble support, …) for deciding fallbacks.
IActionStateProvider Query whether an action (built-in or modded) is active; IDs look like attack / modid:key.name.
IPlayerStateRegistry Push modId:stateName states for JSON playerState conditions. setState is the only call allowed from any thread.
IInteractiveContextRegistrar Declare a custom-drawn overlay foreground / background so Control Flex switches to the Overlay phase while it is up.
ICompatAssetInstaller Install compat / guide assets (available only inside the matching callbacks).

Threading: everything except setState() runs on the client main thread; both getActiveGameActions() and IControllerState are live views — never hold them across ticks.

5. The official compatibility implementations

They fall into three groups, all under the ControlFlexMC organisation:

Repository Type What it solves
control-flex Core Built-in compat JSON + dispatch channels + three-layer override — covers the vast majority of standard KeyMapping mods. The built-in JSON lives in src/main/resources/controlflex/compat/.
cfx-compat-configs Config source Distribution and sharing of community configs, organised by MC version / loader — the ceiling of the "no code" route.
cfx-compat-epicfight Bridge Epic Fight's battle-mode state and dedicated keys; also the most complete example of state pushing plus asset installation.
cfx-compat-emi Bridge EMI keeps its bindings in its own config and registers no KeyMapping; the bridge registers 22 pseudo KeyMappings and forwards presses back into EMI's interaction functions.
cfx-compat-create Bridge Create's train console polls raw key state (InputConstants.isKeyDown); once analog movement takes over, nothing publishes key state, so the bridge has to.
cfx-compat-vehicles Bridge Immersive Vehicles (MTS) calls GLFW.glfwGetKey directly; the bridge puts its mixin inside the vehicle mod's own read path (MTS only for now).
cfx-compat-exposure Bridge Key and screen adaptation for the Exposure camera mod.

Bridges and JSON are not either-or: most bridges also install a JSON into the mods/ layer through onInstallCompatConfigs — letting JSON decide where keys sit, and Java decide what happens at runtime.

6. Three typical failures, three approaches

1) Nothing is registered: add pseudo KeyMappings

The mod stores bindings in its own config and matches them inside its own screens (EMI does exactly this), so the keys appear neither in vanilla Controls nor in auto-discovery. The fix is to register ordinary KeyMappings and forward "pressed" back into the mod's own entry points — no fake input, and the mod's key settings stay untouched. 

// 示意：注册一组伪 KeyMapping（注册 API 随 MC 版本 / 加载器不同）
new KeyMapping("key.cfx_target.open", GLFW.GLFW_KEY_K, "key.categories.cfx_target");

// 每 tick 把 Control Flex 的动作状态转发回模组自己的入口
if (ControlFlexApi.getActionStateProvider()
        .isGameActionActive("cfx_target:key.cfx_target.open")) {
    TargetMod.openPanel();   // 调用模组自己的函数，而不是模拟按键
}

2) The mod polls raw key state: mixin its read path

The glfwPoll channel covers polling through InputConstants.isKeyDown, but mods that call GLFW.glfwGetKey never see it — GLFW is loaded by the system class loader and never passes through ModLauncher's transformer. Instead, put a mixin on the mod's own read entry point and answer "is it held right now". 

// 示意：只回答四个移动键，其余交还原逻辑
@Mixin(TargetInput.class)
public abstract class TargetInputMixin {

    @Inject(method = "isKeyPressed", at = @At("HEAD"), cancellable = true)
    private void cfx$steering(int keyCode, CallbackInfoReturnable<Boolean> cir) {
        if (ControlFlexApi.isAvailable()
                && ControlFlexApi.getActionStateProvider().isGameActionActive("move_forward")) {
            cir.setReturnValue(true);
        }
    }
}

Keeping that mixin inside a separate bridge mod keeps the core free of third-party dependencies, and a failure only affects that one compat package.

3) The mod has runtime state: push it, let JSON consume it

Epic Fight's battle mode decides which keys the mod should own. Java only pushes the state; which actions get suppressed is written in JSON — so players and pack authors can change it. 

// Java：状态变化时推一次
ControlFlexApi.getPlayerStateRegistry()
    .setState("epicfight:battle_mode", inBattle);
// JSON：条件消费（主手拿武士刀且处于战斗模式时，压制通用 use）
"itemSuppressKeys": [
  { "item": "efn:yamato_dmc*",
    "playerState": ["epicfight:battle_mode"],
    "suppressActions": ["use"] }
]

7. Debugging and shipping

  • Log prefix [ModCompat]: loading, overriding and skip reasons all land there; give your bridge its own logger.
  • Guard the minimum API version with requireApiVersion("0.8.7"), and declare Control Flex as a mandatory dependency in mods.toml / fabric.mod.json.
  • API is compileOnly; ship a separate JAR and do not shade it in, or you duplicate the core.
  • In the release notes, say what it fixes, which mod versions and loaders you tested, and whether it ships optional JSON defaults.
