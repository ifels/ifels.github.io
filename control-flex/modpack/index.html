配置文件与整合包Configuration for Modpacks

面向想改默认配置、并让它随整合包一起分发的玩家与包作者：配置放在哪、覆盖规则是什么、模板 JSON 怎么写。 For players and pack authors who want to change defaults and ship them with a pack: where configs live, how overrides resolve, and how template JSON is written.

配置目录结构Config Directory Layout

config/controlflex/
├── templates/          # 模板 JSON（内置 + 自定义）# template JSON (built-in + custom)
├── profiles/           # 每个模板对应的用户修改# per-template user modifications
├── compat/             # 模组兼容配置# mod compatibility configs
│   ├── default/        # 内置（从 JAR 释放，只读）# packaged (extracted from the JAR, read-only)
│   ├── mods/           # 桥接模组安装（只读）# installed by bridge mods (read-only)
│   └── user/           # 你的修改（优先级最高）# your edits (highest priority)
├── guides/             # 引导资源，分层同 compat/# guide assets, same default/mods/user layering
├── radial_menu/        # 径向菜单布局与图标# radial menu layouts and icons
├── backup/             # 升级迁移时的自动备份# automatic backups from migrations
└── cfx-client.json     # 客户端全局状态# global client state

覆盖规则Override Rules

  • 兼容配置分三层，优先级 user > mods > default；同 mod_id 的文件按层整体覆盖。Compat configs resolve in three layers with priority user > mods > default; files with the same mod_id override wholesale by layer.
  • 游戏内编辑是“写时复制”：内置与社区文件保持只读，你的改动落到 compat/user/。Reset Config 会把某个模组恢复为内置或已应用的社区默认。In-game edits are copy-on-write: packaged and community files stay read-only and your changes land in compat/user/. Reset Config restores a mod to its packaged or applied community default.
  • 兼容文件只在目标 mod_id（及其声明的 dependencies）实际加载时生效，未安装的模组配置会被干净跳过。A compat file only activates when its target mod_id (and any declared dependencies) are actually loaded; configs for absent mods are skipped cleanly.

作为整合包分发默认配置Shipping Defaults with a Pack

  1. 先在游戏里调出你满意的键位，然后从 config/controlflex/profiles/ 取对应文件。 Tune the bindings in-game until you are happy, then take the matching file from config/controlflex/profiles/.
  2. 想做成“可选布局”时，把它整理成一个自定义模板放进 config/controlflex/templates/<name>.json —— 它会出现在游戏内的模板切换列表中。 For an optional layout, package it as a custom template at config/controlflex/templates/<name>.json — it appears in the in-game template switcher.
  3. 把 config/controlflex/ 下的相应文件放进整合包的 overrides（如 CurseForge / Modrinth 包的 overrides/config/controlflex/）。玩家的个人改动仍然写进 profiles/ 与 compat/user/，不会丢失。 Put the relevant files from config/controlflex/ into your pack's overrides (e.g. overrides/config/controlflex/ on CurseForge / Modrinth packs). Player edits still go to profiles/ and compat/user/ and are preserved.

模板 JSON 格式Template JSON Format

模板把“动作 → 按键|模式”按层组织起来。以下是内置 Basic 模板的结构（节选）： A template maps “action → button|mode” per layer. This is the structure of the built-in Basic template (excerpt): 

{
  "templateMeta": {
    "name": "basic",
    "displayName": "Basic",
    "description": "Basic controller bindings for Minecraft Java Edition",
    "version": 4
  },
  "mainActionBindings": {
    "layer_shift1": "leftBumper|HOLD",
    "jump": "buttonA|HOLD",
    "sneak": "rightStickClick|HOLD",
    "toggle_sneak": "rightStickClick|DOUBLE_TOGGLE",
    "attack": "rightTrigger|HOLD",
    "drop_stack": "rightStickClick+dpadDown|PRESS",
    "sys_pause": "buttonStart|LONG_PRESS",
    "controlflex:key.controlflex.open_settings": "buttonBack+buttonStart|PRESS"
  },
  "shift1ActionBindings": { "controlflex:key.controlflex.open_radial_menu_2": "buttonBack|HOLD" },
  "shift2ActionBindings": {},
  "shift3ActionBindings": {},
  "shift4ActionBindings": {},
  "guiActionBindings": {
    "inv_select": "buttonA|PRESS",
    "inv_quick_move": "buttonY|TAP",
    "mouse_wheel_up": "rightStickUp|HOLD"
  },
  "overlayActionBindings": {
    "gui_back": "buttonB|PRESS"
  },
  "virtualKbmBindings": {
    "key.keyboard.left.shift": { "guiLayer": { "binding": "leftTrigger", "enabled": true } }
  },
  "thresholds": {
    "tapThresholdMs": 500,
    "longPressThresholdMs": 1000
  }
}

按键 token（ButtonId）Button tokens (ButtonId)

分类Group 取值Values
面键Face buttonsbuttonA · buttonB · buttonX · buttonY
肩键 / 扳机Bumpers / triggersleftBumper · rightBumper · leftTrigger · rightTrigger
摇杆按下Stick clicksleftStickClick · rightStickClick
摇杆方向Stick directionsleftStickUp/Down/Left/Right · rightStickUp/Down/Left/Right
十字键D-PaddpadUp · dpadDown · dpadLeft · dpadRight

背键Paddlespaddle1 – paddle4

模式 token（TriggerMode）Mode tokens (TriggerMode)

PRESS · RELEASE · HOLD · TAP · LONG_PRESS · TOGGLE · DOUBLE_PRESS · DOUBLE_TAP · DOUBLE_HOLD · DOUBLE_TOGGLE

组合键把按键用 + 连接；模式跟在 | 之后。键位字符串按 button1+button2|MODE 的形式书写。 Chords join buttons with +; the mode follows |. A binding string reads button1+button2|MODE.

动作 ID 有四种形态：内置动作（jump）、原版按键（key.jump）、模组按键（epicfight:key.epicfight.attack，即 modId:keyName）以及 ControlFlex 自身按键（controlflex:key.controlflex.open_settings）。最稳妥的做法是在游戏内改好后导出，而不是手写整表。 Action IDs come in four shapes: built-in actions (jump), vanilla keys (key.jump), mod keys (epicfight:key.epicfight.attack, i.e. modId:keyName), and ControlFlex's own keys (controlflex:key.controlflex.open_settings). The safest workflow is to edit in-game and export, rather than hand-writing the whole table.

径向菜单配置Radial Menu Config

径向菜单布局保存在 config/controlflex/radial_menu/radial_menus.json，图标资源放在同目录下；游戏内编辑器更直观，配置库分发时直接带上这个文件即可。 Radial layouts persist in config/controlflex/radial_menu/radial_menus.json with icons alongside them; the in-game editor is easier, and shipping this file in a pack carries the menus along.

版本升级与迁移Upgrades & Migration

从 0.8.6.x 升级到 0.8.7+ 时，配置档案、兼容文件与客户端设置会在首次启动自动迁移，原文件复制到 config/controlflex/backup/。整合包更新模组版本时，玩家的 profiles/ 与 compat/user/ 会被保留。 Upgrading from 0.8.6.x to 0.8.7+ migrates profiles, compat files, and client settings on first launch, copying originals to config/controlflex/backup/. When a pack bumps the mod version, players' profiles/ and compat/user/ are preserved.
