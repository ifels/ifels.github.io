模组兼容性Mod Compatibility

Control Flex 为整合包而生：先自动发现，再按需逐级加码 —— 游戏内适配中心、社区配置库、Compat JSON、桥接模组。 Control Flex is built for modpacks: auto-discovery first, then four escalating tools — the in-game adaptation center, the community config repo, compat JSON, and bridge mods.

第一层：自动发现Layer One: Auto-Discovery

启动时 Control Flex 会扫描 Minecraft 的 KeyMapping 注册表，把每个非原版绑定注册为动态动作。只要模组通过标准方式注册了按键（JEI 配方键、战斗模组技能键、地图快捷键……），就会出现在按键映射中，无需任何配置文件。 At startup Control Flex scans Minecraft's KeyMapping registry and registers every non-vanilla binding as a dynamic action. If a mod registered its keys the standard way (JEI recipe keys, combat-mod skills, map hotkeys…), they show up in Key Mapping with no config file at all.

库类模组会被自动豁免（内置清单覆盖 Fabric API、Kotlin 语言支持等家族），不会混进可适配列表。 Library mods are exempted automatically (the built-in list covers the Fabric API and Kotlin language-support families), so they never clutter the adaptation lists.

内置兼容配置Built-in Compat Configs

模组 JAR 内附带一小撮内置兼容配置，每次启动都会释放到 config/controlflex/compat/default/： A small set of built-in compat configs ships inside the JAR and is extracted to config/controlflex/compat/default/ on every launch:

模组Mod 内置了什么What it provides
Just Enough Items (JEI) 配方 / 用途查看键位（GUI 层）、一批不需要暴露的内部按键加入忽略清单Recipe / uses keys on the GUI layer, plus an ignore list for internal keys that should not be exposed
Epic Fight 战斗模式相关的键位与界面规则；指向官方桥接模组 cfx-compat-epicfightBattle-mode key and screen rules; points to the official cfx-compat-epicfight bridge
Nightfall 该模组的按键与界面适配Key and screen adaptation for the mod

其余模组靠自动发现或社区配置库补充；内置配置只在其目标模组实际安装并加载时生效。 Everything else is covered by auto-discovery or the community repo; built-in configs only activate when their target mod is actually installed and loaded.

第二层：游戏内模组适配中心Layer Two: In-Game Mod Adaptation

打开 Control Flex 设置 → 模组适配：每个已安装模组按名称、图标与版本列出。进入某个模组后有三个页签： Open Control Flex Settings → Mod Adaptation: every installed mod is listed with name, icon, and version. Open a mod to work in three tabs:

页签Tab 用途Purpose
按键绑定Key Bindings 该模组被发现的全部动作；分配层级（Main / Screen / Overlay）并绑手柄按键The mod's discovered actions; assign layers (Main / Screen / Overlay) and bind controller buttons
界面适配Screen Adaptation 该模组界面打开时的摇杆模式、层级映射与光标规则Stick mode, layer mapping, and cursor rules while that mod's GUI is open
叠层适配Overlay Adaptation 对交互式 HUD（法术轮盘、轮盘菜单、拍照 HUD 等）做同样的事The same for interactive HUDs (spell wheels, radial menus, photo HUDs)

添加界面 / 叠层规则的方法：先在游戏里打开目标界面一次，让 Control Flex 记录它；然后在模组详情里点 + 添加界面/叠层适配，从“最近页面”（最多 50 条）中选中即可。无法归属到模组的条目可以自动扫描。 To add a Screen or Overlay rule: open the target GUI or HUD once in-game so Control Flex records it, then use + Add Screen/Overlay Adaptation in the mod's detail page and pick it from the recent-pages list (up to 50). Entries that could not be matched to a mod can be scanned automatically.

每根摇杆在该页面上可以选用不同的行为： Each stick can use a different behavior for that page:

行为Behavior 说明What it does
Independent 摇杆方向作为独立动作，在“层级映射”中绑定；Overlay 默认，以及 Screen 右摇杆默认Stick directions are actions bound on Layer Mapping; the default on Overlay and for the Screen right stick
Radial Path 摇杆描出路径 / 角度 —— 法术轮盘、轮盘菜单类界面Stick traces a path / angle — spell wheels and radial-menu style UIs
Virtual Mouse 摇杆在该界面内移动光标；Screen 左摇杆默认Stick moves a cursor inside that UI; the default for the Screen left stick

没有规则时：Screen 层左摇杆为 Virtual Mouse、右摇杆为 Independent；Overlay 层两杆保持 Independent（即该层的四向绑定）。光标样式可选系统 / 基岩 / 手型；Virtual Mouse 可调光标速度，Radial Path 可调阈值、半径、角度偏置与是否记忆上一次角度。 With no rule: Screen uses Virtual Mouse on the left stick and Independent on the right; Overlay keeps both sticks Independent (the layer's four-way bindings). Cursor style can be system / Bedrock / hand; Virtual Mouse has cursor speed, and Radial Path has threshold, radius, angle bias, and whether the stick restores its last angle.

规则编辑是写时复制：内置与社区文件只读，改动落到 config/controlflex/compat/user/；某个模组的 Reset Config 会恢复到内置或已应用的社区默认。 Rule edits are copy-on-write: packaged and community files stay read-only and changes land in config/controlflex/compat/user/; a mod's Reset Config restores its packaged or applied community default.

第三层：社区配置库Layer Three: Community Configs

官方社区源：ControlFlexMC/cfx-compat-configs。在模组适配里点 Sync Configs，然后浏览变体、预览按键 / 界面 / 叠层内容，确认后 Apply —— 应用前会先备份已有的用户文件。也可以添加自定义远程源，或在模组详情页导入 / 导出本地 JSON。欢迎向该仓库提交新模组的配置 PR。 The official community source is ControlFlexMC/cfx-compat-configs. From Mod Adaptation, hit Sync Configs, browse variants, preview Bindings / Screen / Overlay, and Apply — any existing user file is backed up first. Extra sources can be added, and local JSON can be imported/exported from a mod's detail page. PRs for new mod configs are welcome.

第四层：Compat JSON（整合包作者与高级用户）Layer Four: Compat JSON (pack authors & power users)

JSON 是这套 UI 背后可分享的载体。把文件放到 config/controlflex/compat/user/{mod_id}.json；桥接模组可以把自己的配置打进 compat/mods/（运行时只读）。一份配置可以做到： JSON is the shareable unit behind the UI. Drop files at config/controlflex/compat/user/{mod_id}.json; bridge mods may install theirs into compat/mods/ (read-only at runtime). A config can:

  • 把按键分配到 Main / Screen / Overlay（inGameKeys / screenKeys / overlayKeys）。Place keys on Main / Screen / Overlay (inGameKeys / screenKeys / overlayKeys).
  • 为每个按键选择派发通道（KeyMapping、Forge 事件总线、GLFW 兼容轮询、界面输入）。Choose a dispatch channel per key (KeyMapping, Forge event bus, GLFW-compat polling, screen input).
  • 忽略无用按键（ignoreKeys）、持有指定物品时抑制按键（itemSuppressKeys）、附加提示文案。Ignore unused keys (ignoreKeys), suppress keys while holding an item (itemSuppressKeys), and attach tips.
  • 声明界面 / 叠层的摇杆映射（Independent / Radial Path / Virtual Mouse，与 UI 中的选项一致）。Declare per-screen / per-overlay stick maps (Independent / Radial Path / Virtual Mouse, same options as the UI).

示例结构（节选字段，展示按键分层与状态联动）： Example shape (excerpted fields showing layer placement and state coupling): 

{
  "mod_id": "epicfight",
  "mod_name": "Epic Fight",
  "home_page": "https://www.curseforge.com/minecraft/mc-mods/epic-fight-mod",
  "ignoreKeys": ["key.epicfight.dodge"],
  "inGameKeys": ["epicfight:key.epicfight.attack"],
  "screenKeys": [],
  "overlayKeys": [],
  "itemSuppressKeys": [{
    "item": "mymod:special_weapon",
    "playerState": ["mymod:combat_mode"],
    "suppressActions": ["attack"]
  }]
}

字段全集与取值请以权威字段参考为准：cfx-compat-configs 字段参考（中文） / English。 For the full field set and allowed values, see the authoritative reference: cfx-compat-configs field reference (English) / 中文.

playerState 条件配合桥接模组推送的状态生效（IPlayerStateRegistry，键名形如 modId:stateName）—— 桥接写法见开发者文档。 playerState conditions work together with states pushed by bridge mods (IPlayerStateRegistry, keys shaped modId:stateName) — see the developer docs for the bridge side.

模组有自己的输入系统？用桥接模组Custom Input Systems: Bridge Mods

如果目标模组绕开 KeyMapping、有运行时的战斗状态、或直接读取手柄，就需要一个使用 IControlFlexPlugin SPI 的桥接模组：它可以导出 compat JSON、推送玩家状态、响应控制器插拔。官方范例是 cfx-compat-epicfight（内置 Epic Fight 配置就指向它）。开发者文档见 API 快速开始。 If a mod bypasses KeyMapping, has runtime combat state, or reads the gamepad directly, it needs a bridge mod using the IControlFlexPlugin SPI: export compat JSON, push player states, react to controller lifecycle events. The official example is cfx-compat-epicfight (which the built-in Epic Fight file points to). Start at API Quick Start.

仍然有问题？按这个顺序排查Still Misbehaving? Check in This Order

  1. 看按键映射 —— 这个动作绑到正确的层了吗（Screen / Overlay / Main）？Check Key Mapping — is the action on the right layer (Screen vs Overlay vs Main)?
  2. 打开该模组的模组适配 —— 添加界面 / 叠层规则，或应用社区配置。Open Mod Adaptation for that mod — add a Screen/Overlay rule, or apply a community config.
  3. 如果模组只监听物理键，用虚拟键鼠绑定。If the mod only listens for physical keys, bind it with Virtual KBM.
  4. 手写或分享一份 compat JSON；模组完全绕开 KeyMapping 时，写一个桥接模组。Hand-edit or share a compat JSON; write a bridge if the mod bypasses KeyMapping entirely.
