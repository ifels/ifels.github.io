平台支持Platform Support

Control Flex 通过 libgamepadjni + SDL3 读取手柄。桌面三平台的原生库与 SDL3 都随 JAR 提供，开箱即用；Android 上 SDL3 必须来自启动器 APK，因此不同启动器的行为并不完全一样。 Control Flex reads controllers through libgamepadjni + SDL3. On desktop, both the native library and SDL3 ship inside the JAR, so it works out of the box; on Android, SDL3 must come from the launcher APK, which is why behaviour varies a little between launchers.

平台判定只看 os.version：以 Android- 开头即视为 Android，其余按桌面处理。os.name（Android 启动器同样写 Linux）只用于诊断日志，不参与判定。 Detection reads os.version only: a value starting with Android- means Android, everything else is treated as desktop. os.name (Android launchers also report Linux) is written to diagnostic logs and never used for detection.

桌面平台Desktop

  • 无需安装 SDL3、驱动或额外运行库 —— 模组固定使用 JAR 内打包的 SDL3，不与系统里已有的 SDL 冲突，也不会去搜索系统路径。No SDL3, driver, or extra runtime to install — the mod always uses the SDL3 packaged in the JAR, so it neither conflicts with a system SDL nor searches system paths.
  • Windows 的 x86_64 与 ARM64 都随包提供原生库（gamepadjni.dll + SDL3.dll）。Both Windows x86_64 and ARM64 ship native binaries (gamepadjni.dll + SDL3.dll).
  • macOS 同时提供 Intel 与 Apple Silicon 两份 libgamepadjni.dylib，Rosetta 与否都能用。macOS ships both Intel and Apple Silicon libgamepadjni.dylib builds, so it works with or without Rosetta.
  • Linux 提供 x86_64 与 aarch64 两份 libgamepadjni.so；Steam Deck 之类的 aarch64 设备同样在列。Linux ships x86_64 and aarch64 libgamepadjni.so builds, covering aarch64 devices such as Steam Deck.
  • 手柄热插拔、多手柄识别、按手柄身份（名称 / 类型 / 序列号）记忆配置，在三个桌面平台上行为一致。Hotplug, multi-controller detection, and per-controller identity (name / type / serial) behave the same across the three desktop platforms.

Android（启动器环境）Android (inside a Launcher)

Android 版 Minecraft: Java Edition 由启动器提供的 JVM 运行，手柄链路因此分成两段：SDL3 来自启动器 APK（启动器已经在 ART 侧装好 SDL 的 glue），libgamepadjni.so 由模组自带并按 os.arch 解压加载。两者顺序固定 —— 先 SDL3，再 JNI 桥，否则动态链接器绑不到同一份库。 On Android, Minecraft: Java Edition runs on a JVM provided by a launcher, so the controller path is split in two: SDL3 comes from the launcher APK (the launcher already installed the SDL glue on the ART side), while libgamepadjni.so ships with the mod and is extracted per os.arch. The order is fixed — SDL3 first, then the JNI bridge — or the dynamic linker binds to a different copy.

Android 上的注意事项Android Caveats

不要覆盖 os.version。部分启动器的自定义 JVM 参数或版本 JSON 会把它改成普通内核号（例如 5.0）或干脆不写 Android- 前缀，这时模组会把环境当成桌面 Linux，去加载桌面的 SDL3，结果是手柄在设置里始终不可见。确认启动器注入 -Dos.version=Android-<版本> 没有被你的自定义参数覆盖。 Do not override os.version. Some launchers' custom JVM arguments or version JSON replace it with a plain kernel number (e.g. 5.0) or drop the Android- prefix. The mod then treats the JVM as desktop Linux, loads a desktop SDL3, and the controller never shows up in settings. Make sure the launcher's -Dos.version=Android-<release> is not overridden by your own arguments.

  • JAR 里没有 Android 版 libSDL3.so；不要在 mods 目录旁边再塞一份 SDL3，加载到没有启动器 glue 的 SDL 会让手柄永远不可见。The JAR ships no Android libSDL3.so; do not drop another SDL3 next to your mods. Loading an SDL without the launcher glue makes controllers permanently invisible.
  • 需要自带 libgamepadjni.so 时，把 CFX_LIB_PATH 指向包含该文件的目录（系统属性优先于环境变量）。To supply your own libgamepadjni.so, point CFX_LIB_PATH at the directory holding it (system property wins over environment variable).
  • Android 上 SDL 与启动器共用同一个进程实例，所以退出游戏时模组不会 SDL_Quit 整个库，避免拆掉启动器的 video / glue。On Android, SDL is shared with the launcher inside one process, so the mod never SDL_Quits the whole library on shutdown — that would tear down the launcher's video / glue.
  • 配置目录仍是 config/controlflex/，相对启动器为实例指定的游戏目录；换启动器（或换实例目录）时，配置不会自动跟过去。The config directory is still config/controlflex/, relative to the game directory the launcher assigned to that instance; switching launchers (or instance dirs) does not carry configs over.
  • 震动、光标、分屏这类功能的实际可用度取决于启动器窗口模型与设备：分屏为桌面多实例场景设计，Android 上一般无法同时跑两个实例。Rumble, cursor, and split-screen availability depends on the launcher's window model and the device: split-screen targets multi-instance desktop setups, and Android devices normally cannot run two instances side by side.
