功能详解Features

按“一条输入链路”的顺序介绍：先看按键被分到哪一层，再看它什么时候触发、能组合出什么，最后是围绕它的菜单、移动、镜头、震动与兼容能力。 Following one input path end to end: which layer a button lands on, when it fires, what it can chord into — then the menus, movement, camera, rumble, and compatibility features built on top.

1. 七层按键架构1. Seven Binding Layers

一个手柄大约只有十几个输入，而一个整合包可能暴露上百个动作。ControlFlex 用七层模型让同一个物理按键在不同场景承担不同职责： A controller has roughly a dozen inputs; a modpack can expose hundreds of actions. The seven-layer model lets one physical button mean different things per context:

层Layer 何时生效Active when 说明Notes
Main 游戏内默认层Default in-game 移动、战斗、快捷栏、常用模组动作Movement, combat, hotbar, everyday mod actions
Shift 1–4 按住层切换键时While a layer switch is held 修饰层：空槽位自动继承 Main 的同名绑定，只需覆盖要改的项；松开切换键自动回 MainModifier planes: unassigned slots inherit the matching Main binding; releasing the switch returns to Main
Screen 任意界面打开时（背包、箱子、模组 UI、设置）Whenever a screen is open (inventory, chests, mod UIs, settings) 确认、返回、切页、滚动、槽位跳转、容器辅助操作Confirm, back, tab switching, scrolling, slot navigation, container helpers
Overlay 交互式 HUD 打开时（法术轮盘、第三方轮盘、拍照 HUD 等）Interactive HUDs (spell wheels, third-party radial menus, photo HUDs) 显式绑定、不继承 Main：未配置的动作保持静默，避免 HUD 误触发战斗键Explicit bindings, no Main inheritance: unconfigured actions stay silent so a HUD cannot misfire combat keys

层切换键在 Main 层使用固定 Hold 模式；Shift 层自动派生一个 Release 模式的“返回 Main”绑定。Overlay 打开期间层切换会被抑制；需要跨界面保持按住的按键可以用相位锁定（phase-lock）延续到解锁。 Layer switches on Main use fixed Hold; each Shift layer auto-derives a Release “return to Main”. Layer switches are suppressed while an overlay is open; keys that must stay held across an overlay or screen can be phase-locked until you unlock them.

2. 十种触发模式2. Ten Trigger Modes

每个绑定由「哪个键」和「怎么触发」两部分组成。同一颗按键可以同时承担单击、长按、切换和双击行为： Every binding pairs which button with how it fires. The same face button can tap, hold, toggle, and double-press for different actions:

模式Mode 触发时机When it fires 典型用途Typical use
Press按下瞬间On button down一次性动作、开关类操作One-shot actions, opening menus
Release松开瞬间On button upShift 层返回 Main、“松手生效”的动作Layer return, “on let go” actions
Hold按住期间持续While held移动类修饰、持续使用、层切换键Movement modifiers, sustained use, layer switches
Tap短于阈值的按下并松开Short press under threshold不误触发长按的快速动作Quick actions without accidental holds
Long Press按住超过阈值后Held past threshold同一按键的第二功能Secondary function on the same button
Toggle第一次按开、第二次按关First press on, second off持续状态：疾跑、走路模式、视角切换Persistent states: sprint, walk mode, POV
Double Press在 Tap 窗口内第二次按下（按下即触发）Second press inside the tap window (fires on down)与 Hold / Press 共用一颗键的额外单击An extra one-shot alongside Hold / Press
Double Tap两次短按，第二次松开时触发Two short presses; fires on the second release不抢占第一次点击的确认类动作Confirm-style actions without stealing the first tap
Double Hold短按后，在窗口内按住Short press, then press-and-hold inside the window轻点再接长按才触发，例如防误触的疾跑 / 潜行Tap-then-hold for sprint or sneak, avoiding misfires
Double Toggle与 Toggle 同锁存，第二次轻按翻转Same latch as Toggle; flips on the second tap与 Hold 版本共用一颗键的锁定切换Latch sneak/sprint on the same button as the hold version

Tap 与 Long Press 阈值全局可调（100–2000 ms）；Tap 阈值同时也是所有双击模式中两次按键的最大间隔。默认值：Tap 500 ms / Long Press 1000 ms。 Tap and Long Press thresholds are globally configurable (100–2000 ms); the Tap threshold is also the max gap between taps in every Double mode. Defaults: Tap 500 ms / Long Press 1000 ms.

3. 组合键（Combo Keys）3. Combo Keys

一颗不够就按下多颗：把 LB + Back 或 LT + A 这样的和弦绑定到一个动作。捕获时先按第一颗键，在 500 ms 内追加其余按键，界面会显示完整和弦。 When one button is not enough, bind a chord such as LB + Back or LT + A to a single action. During capture, press the first button and add the rest within 500 ms; the UI shows the full chord.

  • 全模式通用：和弦同样支持全部十种触发模式，规则与单键绑定一致。Works with every mode: combos support all ten trigger modes, same rules as single-key binds.
  • 升级规则：更大的和弦激活时（如 A+B+Y），其已激活的真子集（A+B）会被清除，行为保持可预测。Upgrade rule: activating a larger chord (e.g. A+B+Y) clears smaller active subsets (A+B) so behavior stays predictable.
  • 按键共享：一颗物理按键可通过引用计数参与多个和弦。Button sharing: one button can participate in several combos via reference counting.
  • Shift + 和弦：先按住修饰键，再在对应层上按和弦 —— 扩展布局而不占用 Main 层槽位。Shift + combo: hold a modifier first, then chord on that layer — extending layouts without spending Main slots.

4. 径向菜单4. Radial Menus

最多 5 个独立轮盘，每个轮盘环绕摇杆至多 8 个槽位：打开轮盘、用摇杆瞄准、按 A 确认。 Up to five independent wheels, each with up to eight slots around the stick: open a wheel, aim with the stick, confirm with A.

槽位类型Slot type 作用What it does
按键Key binding触发原版或模组的 KeyMappingFires a vanilla or mod KeyMapping
命令Command执行聊天命令，如 /home、/warpRuns a chat command such as /home or /warp
使用物品Use item切换到并快速使用某个快捷栏物品（火把、食物、工具）Switches to and uses a hotbar item (torches, food, tools)
  • 打开方式：每个轮盘有自己的打开绑定 —— Press 为轻按打开（松手不关闭），Hold 为按住保持、松开关闭。Opening: each wheel has its own open binding — Press taps to open (release does not close), Hold keeps it open while held.
  • 选择摇杆：左摇杆、右摇杆或双摇杆。Selection stick: left, right, or both.
  • 图标：自动、随机、默认、物品 ID 或自定义贴图路径。Icons: auto, random, default, item ID, or a custom texture path.
  • 布局：保存在 config/controlflex/radial_menu/radial_menus.json，可在游戏内编辑器中调整图标、顺序与触发方式。菜单 2–5 通常放在 Shift 层上，让 Main 保持干净。Layouts: persist in config/controlflex/radial_menu/radial_menus.json and are editable in-game (icons, order, trigger mode). Menus 2–5 usually live on Shift layers to keep Main clean.

5. 模拟移动（360°）5. Analog Movement (360°)

原版 Minecraft 只把 WASD 当作开关，因此“摇杆转按键”只能八方向全速行走。开启模拟移动后，ControlFlex 直接提供连续的 360° 移动向量：任意角度，轻推即慢走。 Vanilla Minecraft only sees WASD as on/off, so stick-to-keys walking is limited to eight directions at full speed. With Analog Movement, ControlFlex feeds a continuous 360° vector: any angle, and a light push walks slowly.

路径：ControlFlex 设置 → 其他（Other）→ 模拟移动。Path: ControlFlex Settings → Other → Analog Movement.

策略Policy 行为Behavior
Analog Smooth方向与推杆幅度原样使用，主机手感Direction and magnitude used as-is — the console feel
键盘式 8 向Keyboard-like 8-way摇杆吸附到八个方向、全速行走，在服务器看来与键盘输入一致Stick snapped to eight directions at full speed, which looks like keyboard input on a server

默认策略随连接场景变化：单机 / 局域网使用 Analog Smooth；公共服务器与 Realms 使用键盘式 8 向。确需在远程服务器使用 Analog Smooth 时，可在同一页面把服务器（host:port 或 Realm 名）加入白名单。 Defaults follow the connection: singleplayer / LAN uses Analog Smooth; public servers and Realms use keyboard-like 8-way. If a remote server should still use Analog Smooth, whitelist it (host:port or Realm name) on the same page.

6. 镜头与光标6. Camera & Cursor

  • 右摇杆视角：可调灵敏度与 Y 轴反转；三种模式 —— Direct Turn（直接转向）、Smooth Turn（平滑转向）、Simulate Mouse（走鼠标管线，兼容 Epic Fight 等战斗模组）。Right-stick look: configurable sensitivity, optional Y-invert, and three modes — Direct Turn, Smooth Turn, and Simulate Mouse (routes look through the mouse pipeline for combat mods such as Epic Fight).
  • 虚拟光标：界面打开时用左摇杆驱动光标。Virtual cursor: the left stick drives the cursor while a screen is open.
  • D-Pad 槽位跳转：在背包与容器格子间直接跳转（锥形瞄靶，不规则格网同样适用），左摇杆仍可自由移动光标。D-Pad slot navigation: jumps the cursor between inventory and container slots (cone targeting, works on irregular grids) while the left stick still moves the cursor freely.
  • 槽位吸附：可选，摇杆停止时光标自动吸附到最近格子，便于精确操作容器。Slot snap: optional; when the stick stops, the cursor snaps to the nearest slot for precise container work.

7. 震动反馈7. Rumble

按事件类型分别配置的震动反馈： Vibration feedback configured per event type:

  • 波形模式：无、脉冲、双脉冲、渐强、持续、衰减、心跳等。Waveform modes: none, pulse, double-pulse, crescendo, sustained, fade, heartbeat, and more.
  • 伤害类型：摔落、火焰、溺水、生物、玩家、爆炸、其他，以及击杀事件。Damage types: fall, fire, drown, mob, player, explosion, other — plus entity-kill events.
  • 强度分级：轻 / 中 / 重三档强度阈值。Intensity bands: light / medium / heavy thresholds.

8. 虚拟键鼠（Virtual KBM）8. Virtual Keyboard & Mouse

有些模组从不注册 KeyMapping —— 它们只监听物理键盘或鼠标。虚拟键鼠让手柄直接向游戏注入这些真实按键（Shift、Escape、Page Up/Down、鼠标按键、滚轮），无需先把它们变成 ControlFlex 动作。 Some mods never register a KeyMapping — they only watch the physical keyboard or mouse. Virtual KBM lets the gamepad inject those real keys (Shift, Escape, Page Up/Down, mouse buttons, scroll wheel) on any layer, without turning them into ControlFlex actions first.

  • 捕获一个键盘 / 鼠标按键，然后把任意手柄组合绑定到它。Capture a keyboard/mouse key, then bind any controller combo to it.
  • 轻按滚轮滚动一格；按住则连续滚动（默认 100 ms 一次，可配置）。Tap scrolls the wheel one notch; hold repeats (default 100 ms, configurable).
  • 界面返回键（B）发送物理 Esc，与鼠标点击 Esc 效果一致。GUI Back (B) sends physical Esc, matching a mouse press of Esc.
  • 注入的按键不会输入到聊天栏或文本框。Injected keys never type into chat or text fields.

9. 分屏双人（Couch Co-op）9. Split-Screen Couch Co-op

Java 版不在同一窗口渲染两名玩家，因此本地双人 = 同一台电脑上开两个客户端，通过“对局域网开放”联机。ControlFlex 为此做了准备： Java Edition does not render two players in one window, so couch co-op means two (or more) instances on the same PC joined over Open to LAN. ControlFlex is built for that:

  1. 准备两个以上的 Minecraft 账号，以及两把手柄（或一把手柄 + 键鼠）。Two or more Minecraft accounts, and two gamepads (or one gamepad plus keyboard & mouse).
  2. 每个需要手柄的客户端都安装 ControlFlex；建议都保持窗口模式（不要全屏）。Install ControlFlex in each pad-driven instance; keep both windows windowed (not fullscreen).
  3. 在两个客户端的 手柄选择里分别指定不同的手柄，避免互相抢占；手柄 + 键鼠时只为其中一个实例选手柄。In each game's Gamepad Selection, pick a different controller so they do not steal each other; for pad + keyboard, assign the pad only in the gamepad instance.
  4. 每个窗口按 F3+P 关闭“失去焦点时暂停”（或在视频设置中调整）—— 后台窗口必须继续运行。Press F3+P in each window to disable Pause on Lost Focus (or use video options) — the unfocused window must keep running.
  5. 在其中一个实例上开启“对局域网开放”，其他实例通过局域网列表或 localhost + 端口加入。Host a world from one instance (Open to LAN); join from the others via the LAN list or localhost plus the port.

可选安装 Splitscreen Support（仅做窗口平铺，不处理输入），按 F11 循环半屏 / 四分之一屏布局。后台窗口建议使用 Direct Turn 或 Smooth Turn 视角；Simulate Mouse 无法驱动后台窗口的系统光标，会自动回退。 Optionally install Splitscreen Support (window tiling only, no input handling) and press F11 to cycle half-/quarter-screen layouts. Use Direct Turn or Smooth Turn in background windows; Simulate Mouse cannot drive the OS cursor there and falls back automatically.

10. 模组适配10. Mod Adaptation

ControlFlex 为整合包而生。大多数模组无需任何额外文件：启动时会扫描 Minecraft 的 KeyMapping 注册表，把每一个非原版绑定变成可绑定的动作 —— JEI 配方键、战斗模组技能键、地图快捷键，只要模组注册了按键，就会出现在按键映射里。 ControlFlex is built for modpacks. Most mods work with no extra files: at startup it scans Minecraft's KeyMapping registry and exposes every non-vanilla binding as a bindable action — JEI recipe keys, combat-mod skills, map hotkeys, whatever the mod registered.

当自动发现不够用时（层级不对、HUD 需要自己的摇杆行为、模组根本不注册按键），0.8.7 提供了递进的四种手段：游戏内 模组适配中心 → 社区配置库 → Compat JSON → 桥接模组。 When auto-discovery is not enough (wrong layer, a HUD that needs its own stick behavior, or a mod that never registered keys), 0.8.7 gives you four escalating tools: the in-game Mod Adaptation center → the community config repo → compat JSON → bridge mods.

这一部分的完整玩法（Screen / Overlay 规则、摇杆行为、社区配置同步、JSON 字段与排查流程）在 模组兼容性页面展开。 The full workflow (Screen / Overlay rules, stick behaviors, community config sync, JSON fields, and troubleshooting) lives on the Mod Compatibility page.
