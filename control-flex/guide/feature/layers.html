七层按键架构Seven Layers

标准手柄只有十几个输入，一个整合包却能暴露上百个动作。七层模型让同一个物理按键在不同场景承担不同职责 —— 这是 Control Flex 所有其他功能的地基。 A standard pad has roughly a dozen inputs; a modpack can expose hundreds of actions. The seven-layer model lets one physical button mean different things per context — it is the foundation everything else builds on.

七层一览The Seven Layers

层Layer 何时生效Active when 说明Notes
Main 游戏内默认层Default in-game 移动、视角、战斗、快捷栏与日常模组动作Movement, look, combat, hotbar, and everyday mod actions
Shift 1–4 按住对应的层切换键时While the matching layer switch is held 四个修饰层，各有一整张绑定表；松开切换键自动回到 MainFour modifier planes, each with a full binding table; releasing the switch returns to Main
Screen 任意界面打开时（背包、箱子、模组 UI、设置）Whenever a screen is open (inventory, chests, mod UIs, settings) 确认、返回、切页、滚动、槽位跳转与容器操作；打开界面不会和游戏内键位打架Confirm, back, tab switching, scrolling, slot navigation, container helpers; opening a menu never fights your gameplay bindings
Overlay 交互式 HUD 打开时（法术轮盘、第三方轮盘菜单、拍照 HUD 等）Interactive HUDs (spell wheels, third-party radial menus, photo HUDs) 显式绑定、不继承 Main：未配置的动作保持静默，HUD 不会误触发战斗键Explicit bindings, no Main inheritance: unconfigured actions stay silent so a HUD cannot misfire combat keys

Shift 1–4：完全显式的修饰层Shift 1–4: Fully Explicit Planes

Shift 层是四个独立的绑定平面。理解下面四条规则，就理解了这个功能： Shift layers are four independent binding planes. Four rules explain the whole feature:

  • 移动 / 视角键默认沿用 Main 的值（模板生成时就填好了），其余动作默认未绑定 —— 也就是“完全显式”。Movement and look keys default to Main's values (pre-filled when the template is created); everything else defaults to unbound — the layers are fully explicit.
  • 之后修改 Main 不会同步到 Shift 层；反之亦然。每一层自己说了算。Editing Main later does not change Shift layers, and vice versa. Each layer owns its table.
  • 层切换键固定为 HOLD（Main 层的 layer_shift1–4 四项不可改成其他模式）。Layer switches are fixed to HOLD (the layer_shift1–4 rows on Main cannot use another mode).
  • 每个 Shift 层自动派生一个“返回 Main”绑定，模式为 RELEASE —— 松开切换键即回到 Main，无需手动配置。Each Shift layer auto-derives a “return to Main” binding with RELEASE mode — releasing the switch returns you, no manual setup.

常见误解：Shift 层不是“空槽位实时继承 Main”。运行时不存在回退 —— 空槽就是未绑定。模板只是把移动 / 视角的默认值预先填成和 Main 一样，方便你上手。 Common misconception: Shift layers do not inherit Main at runtime — an empty slot is simply unbound. Templates merely pre-fill movement and look with Main's values so you have a sensible starting point.

Screen 层：界面里的那套键位Screen: Bindings for Menus

只要有任何界面打开，输入就切换到 Screen 层。默认分成四组： Whenever any screen is open, input switches to the Screen layer. Defaults fall into four groups:

  • 光标：左摇杆驱动虚拟光标（也可用方向绑定做光标导航，两者是独立的绑定项）。Cursor: the left stick drives the virtual cursor (direction bindings can navigate it too; the two are separate rows).
  • 槽位：D-Pad 在格子之间跳转，A 选格，Y 快速移动（Shift+点击），X 取一半。Slots: D-Pad jumps between slots, A selects, Y quick-moves (shift-click), X takes half.
  • 导航：A 确认、B 返回 / 关闭、LB/RB 切页（创造标签页、配方书页、指南列表等）。Navigation: A confirm, B back/close, LB/RB switch pages (creative tabs, recipe-book pages, the guide list).
  • 滚动：右摇杆上/下模拟滚轮，左/右轻按切换选项。Scrolling: right stick up/down emulates the wheel; left/right taps cycle options.

Screen 层还能模拟滚轮等物理按键（见虚拟键鼠）；光标行为细节见光标与界面操作。 The Screen layer can also inject physical keys such as the scroll wheel (see Virtual Keyboard & Mouse); cursor details live in Cursor & GUI.

Overlay 层：交互式 HUDOverlay: Interactive HUDs

Overlay 层覆盖既不是完整界面、也不是普通游戏画面的交互式 HUD —— 法术轮盘、第三方轮盘菜单、拍照 / 附件类 HUD。它的默认值贴近游戏手感（移动、视角、跳跃、攻击、使用、滚动），并以 B 作为返回。两个要点： The Overlay layer covers interactive HUDs that are neither a full screen nor plain gameplay — spell wheels, third-party radial menus, photo/attachment HUDs. Its defaults follow the in-game feel (move, look, jump, attack, use, scroll) with B as back. Two things matter:

  • 不继承 Main：没配置的动作在 Overlay 相位保持静默，避免 HUD 打开时误触发战斗键位。HUD 打开期间层切换也会被抑制。No Main inheritance: unconfigured actions stay silent during an overlay, so a HUD cannot misfire combat keys. Layer switches are suppressed while an overlay is open.
  • 需要把 HUD 声明为交互式上下文：游戏内在模组适配里为它添加 Overlay 规则；模组作者可以用 Control Flex API 的 IInteractiveContextRegistrar 主动声明（见API 参考）。需要跨界面保持按住的按键可用相位锁定延续到解锁。The HUD must be declared: add an Overlay rule for it in Mod Adaptation, or use the Control Flex API's IInteractiveContextRegistrar from a bridge mod (see the API Reference). Keys that must stay held across an overlay can be phase-locked until you unlock them.

层归属在哪里改Editing Layers

  • 按键映射页按层显示与编辑：切换层标签，或直接改某一层的行。Key Mapping shows and edits bindings per layer: switch the layer tab, or edit any layer's rows.
  • 一个动作出现在哪些层，在动作详情页按动作设置；切换模板会把层归属重置为模板默认，而“重置为模板默认设置”不会改变层归属。Which layers an action appears on is configured per action in its detail page. Switching templates resets layer placement to template defaults; “reset to template defaults” does not change layer placement.
  • 点击手柄按键栏捕获输入；捕获中 ESC 取消；右键行可清除、重置或改变层归属。Click the controller column to capture input; ESC cancels; right-click a row to clear, reset, or change its layer.

想扩展层级之外的能力：组合键给单个层加压，径向菜单把高频动作收进轮盘。 To go beyond layers: combo keys add density to a single layer, and radial menus keep frequent actions on a wheel.
