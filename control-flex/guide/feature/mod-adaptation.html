模组适配Mod Adaptation

Control Flex 为整合包而生：大多数模组开箱即用；当某个模组不在正确的位置、或界面里的摇杆行为不对时，用模组适配中心逐级解决 —— 游戏内中心 → 社区配置库 → compat JSON → 桥接模组。 Control Flex is built for modpacks: most mods work out of the box. When one sits on the wrong layer or its screen misbehaves, the adaptation chain solves it in escalating steps — in-game center → community repo → compat JSON → bridge mod.

第一层：自动发现Step One: Auto-Discovery

启动时扫描 Minecraft 的 KeyMapping 注册表，把每个非原版绑定注册为可绑定动作；打开设置时还会再对齐一次（reconcile），因此游戏中途换的模组也不会漏。库类模组（Fabric API、Kotlin 语言支持等家族）会被自动豁免，不混进列表。 At startup Control Flex scans Minecraft's KeyMapping registry and registers every non-vanilla binding as a bindable action, then reconciles again when you open settings — so nothing gets missed. Library mods (the Fabric API and Kotlin language-support families) are exempted and never clutter the lists.

第二层：游戏内适配中心Step Two: The In-Game Center

打开 Control Flex 设置 → 模组适配：每个已安装模组按名称、图标与版本列出。进入某个模组有三个页签： Open Control Flex Settings → Mod Adaptation: every installed mod is listed with name, icon, and version. Each mod has three tabs:

  • 按键绑定：该模组被发现的全部动作，分配层级（Main / Screen / Overlay）并直接绑手柄按键。Key Bindings: the mod's discovered actions, assigned to layers (Main / Screen / Overlay) and bound straight to gamepad buttons.
  • 界面适配：该模组的 GUI 打开时的摇杆模式、层级映射与光标规则。Screen Adaptation: stick mode, layer mapping, and cursor rules while that mod's GUI is open.
  • 叠层适配：同样的事，针对交互式 HUD（法术轮盘、拍照 HUD 等）。Overlay Adaptation: the same, for interactive HUDs (spell wheels, photo HUDs, and similar).

添加一条界面 / 叠层规则：先在游戏中把目标界面打开一次让 Control Flex 记录它，然后在模组详情里点 + 添加界面/叠层适配，从“最近页面”（最多 50 条）里选中即可。偶尔遇到无法归属到模组的条目，可以自动扫描。 Adding a rule: open the target GUI or HUD once in-game so Control Flex records it, then use + Add Screen/Overlay Adaptation in the mod's page and pick it from the recent-pages list (up to 50). Entries that could not be matched to a mod can be scanned automatically.

摇杆行为：三选一Stick Behavior: Three Choices

行为Behavior 说明What it does 默认出现在Default for
Independent 摇杆方向当作动作，在层级映射里绑定Stick directions act as actions bound on Layer Mapping Overlay 双摇杆；Screen 右摇杆Both sticks on Overlay; the right stick on Screen
Radial Path 摇杆描出路径 / 角度 —— 法术轮盘、圆环菜单类界面Stick traces a path or angle — spell wheels and ring menus 需手动指定Assigned manually
Virtual Mouse 摇杆在该界面内移动光标Stick moves a cursor inside that UI Screen 左摇杆The left stick on Screen

没有规则时：Screen 层左摇杆为虚拟鼠标、右摇杆为 Independent；Overlay 层两杆都保持 Independent。光标样式可选系统 / 基岩 / 手型；Virtual Mouse 可调光标速度，Radial Path 可调阈值、半径、角度偏置与是否记忆上次角度。 With no rule: Screen uses Virtual Mouse on the left stick and Independent on the right; Overlay keeps both sticks Independent. Cursor style offers system / Bedrock / hand; Virtual Mouse has a speed setting, and Radial Path has threshold, radius, angle bias, and whether the last angle is restored.

第三层：社区配置库Step Three: The Community Repo

官方社区源是 ControlFlexMC/cfx-compat-configs。在模组适配里点 Sync Configs → 浏览变体 → 预览按键 / 界面 / 叠层 → Apply；应用前会先备份已有的用户文件。也支持添加自定义远程源，或在模组详情页导入 / 导出本地 JSON。 The official community source is ControlFlexMC/cfx-compat-configs. From Mod Adaptation: Sync Configs → browse variants → preview Bindings / Screen / Overlay → Apply (existing user files are backed up first). Extra sources can be added, and local JSON can be imported or exported from a mod's page.

你的修改存在哪里Where Your Edits Go

所有编辑都是写时复制：内置与社区文件保持只读，你的改动落到 config/controlflex/compat/user/。某个模组的 Reset Config 会把该模组恢复为内置或已应用的社区默认。内置配置藏在每个模组的规则背后 —— 模组 JAR 自带 JEI、Epic Fight、Nightfall 三份，且只在目标模组实际加载时生效。 All edits are copy-on-write: packaged and community files stay read-only and your changes land in config/controlflex/compat/user/. A mod's Reset Config restores its packaged or applied community default. Packaged rules sit behind every mod — the JAR ships three (JEI, Epic Fight, Nightfall), and each only activates when its target mod is actually loaded.

第四层：仍然不行怎么办Step Four: If It Still Misbehaves

  1. 检查按键映射 —— 这个动作绑在正确的层了吗？Check Key Mapping — is the action on the right layer?
  2. 为它添加界面 / 叠层规则，或应用社区配置。Add a Screen/Overlay rule, or apply a community config.
  3. 只认物理键 → 虚拟键鼠。Physical keys only → Virtual KBM.
  4. 完全绕开 KeyMapping → 手写 / 分享 compat JSON，或写一个桥接模组。Bypasses KeyMapping entirely → hand-write or share compat JSON, or write a bridge mod.

compat JSON 的字段、分层优先级与整合包分发方式，见模组兼容性；桥接模组开发见API 快速开始。 For compat JSON fields, layer priority, and pack distribution, see Mod Compatibility; for bridge-mod development, see API Quick Start.
