MC 版本支持Minecraft Versions

从 1.7.10 到 26.3，Control Flex 覆盖 13 个 MC 版本。功能在各版本线上保持一致，差别在加载器、Java 版本与前置依赖 —— 装错这三样里的任何一样，模组都不会被加载。 From 1.7.10 to 26.3, Control Flex covers 13 Minecraft versions. Features are the same across every line; what differs is the loader, the Java version, and the dependencies — get any of those wrong and the mod simply will not load.

所有版本线使用同一个模组版本号（0.8.9），并内置同一份手柄桥 cfx-gamepadjni 0.9.6.1。Java 版本由该 MC 版本本身决定，不是由平台决定。 Every line ships the same mod version (0.8.9) and the same bundled controller bridge, cfx-gamepadjni 0.9.6.1. The Java version is dictated by that Minecraft version, not by your OS.

三代的差别Three Generations

Forge 时代：1.7.10 – 1.12.2Forge era: 1.7.10 – 1.12.2

  • 只有 Forge 版。这四个版本的年代早于 Fabric 的普及，不存在 Fabric 构建。Forge only. These four predate Fabric's adoption, so no Fabric build exists.
  • Java 8 运行；模组字节码同样针对 Java 8。Runs on Java 8; the mod bytecode targets Java 8 as well.
  • 元数据走旧式 mcmod.info；Mixin 配置与新版不同，但键位、层、径向菜单等行为与新版一致。Metadata uses the legacy mcmod.info; Mixin configs differ from newer versions, but bindings, layers, radial menus, and the rest behave the same.

双加载器时代：1.16.5 – 1.20.1Dual-loader era: 1.16.5 – 1.20.1

  • Forge 与 Fabric 各出一份 JAR，按加载器选文件。One JAR per loader (Forge and Fabric) — pick the file for your loader.
  • Java 版本在这里跳了一档：1.16.5 仍是 Java 8，1.18.2 起是 Java 17。1.16.5 不需要 Java 17。Java jumps here: 1.16.5 is still Java 8, and Java 17 starts at 1.18.2. 1.16.5 does not need Java 17.
  • Fabric 版必须另装 Fabric API，且版本要跟上表对上；Forge 版无需额外前置。Fabric builds require Fabric API at or above the version in the table; Forge builds have no extra dependencies.

NeoForge 时代：1.21.1 起NeoForge era: 1.21.1 and newer

  • 加载器换成 NeoForge + Fabric：1.21 之后不再有 Forge 版，拿 Forge 版去装会直接加载失败。Loaders become NeoForge + Fabric: there is no Forge build past 1.20.1, and a Forge build will simply fail to load.
  • Java 21 起步；26.x 系列要求 Java 25。Java 21 and up; the 26.x series requires Java 25.
  • 26.1.2 / 26.2 / 26.3 共用一条版本线（stonecutter 多目标），Fabric API 的下限由 Fabric API 自身决定。26.1.2 / 26.2 / 26.3 share one line (stonecutter multi-target); the Fabric API floor is set by Fabric API itself.

每个版本线要装什么What to Install per Line

  1. 先确定三件事：MC 版本 → 加载器（Forge / NeoForge / Fabric）→ 对应版本的 Java。Pin down three things first: MC version → loader (Forge / NeoForge / Fabric) → matching Java version.
  2. 在 CurseForge Files 里选与这两项都一致的文件（文件名带 MC 版本与加载器标识）。In CurseForge Files, choose the file matching both (filenames carry the MC version and the loader).
  3. Fabric 版本线额外装 Fabric API；Forge / NeoForge 版本线不要装 Fabric API。On Fabric lines, add Fabric API; on Forge / NeoForge lines, do not.
  4. 把 JAR 放进 mods/，启动游戏；SDL3 无需单独安装（详见 平台支持）。Drop the JAR into mods/ and launch; SDL3 needs no separate install (see Platform Support).

版本线的功能是同一份代码库编译出来的：1.7.10 上的层、触发模式、组合键、径向菜单、模组适配、震动、分屏等，与 26.3 上一致。遇到某个功能在旧版本上“看起来不一样”，先怀疑界面适配差异，而不是功能缺失。 All lines compile from the same codebase: layers, trigger modes, combo keys, radial menus, mod adaptation, rumble, and split-screen on 1.7.10 behave the same as on 26.3. If a feature “looks different” on an older line, suspect UI adaptation differences rather than a missing feature.

配置在版本之间的复用Reusing Configs Across Lines

  • 所有版本线的配置根目录都是 config/controlflex/（templates/、profiles/、compat/、radial_menu/、guides/、keyboard/、backup/），目录结构一致。Every line uses config/controlflex/ as its config root (templates/, profiles/, compat/, radial_menu/, guides/, keyboard/, backup/) with the same layout.
  • 跨版本线复制配置通常可用，但字段会随版本演进增加；复制前先备份，遇到解析失败就让游戏重新生成默认。Copying configs between lines usually works, but fields grow over time; back up first, and let the game regenerate defaults if parsing fails.
  • 从 0.8.6.x 升级会自动迁移，原文件备份在 config/controlflex/backup/。Upgrades from 0.8.6.x migrate automatically, with originals kept under config/controlflex/backup/.
