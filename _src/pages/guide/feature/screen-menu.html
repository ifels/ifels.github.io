Features

Screen Menu

A Screen Menu is a bindable list of actions that opens on top of any screen Control Flex knows about — inventories, quest books, mod GUIs — without closing the screen underneath. Open it with a button, pick an entry, and the action fires as if you had navigated there yourself. Requires Control Flex 0.9+.

How It Works

  • Five menus, five bindings: screen_menu_open_1 – screen_menu_open_5 are regular rebindable actions, bound out of the box.
  • Drawn over the screen: the menu renders as a list panel on top of whatever screen is open; while it is up, a modal input mask keeps clicks and keys away from the screen underneath.
  • Slots come from compat + config: a mod's compat entry (or your own config) can prefill a menu with actions; unusable slots are filtered out at load.
  • One action per slot: hand-edited JSON gets the same validation as the in-game editor.

Where Menu Actions Come From

  • Slots hold key-binding actions only: a slot's actionId points at a rebindable key action, written as modId:key — for example jei:key.jei.showUses.
  • The key must apply to that screen: a mod key is only offered and usable on screens where it actually fires — the mod's own screens plus addToScreens, minus removeFromScreens. This is exactly the editor's candidate list; there are no built-in menu actions right now.
  • Load-time filtering: blank ids, gui_press / inv_select (meaningless with the cursor hidden), screen_menu_open_* (no menus inside menus), non-GUI-layer actions, and actions that fail to resolve are all dropped at load, with the original order preserved.
  • Cross-mod keys are fine: a menu may reference another mod's keys (JEI actions inside a vanilla-inventory menu, say); the menu itself just lives in the compat config of the mod that owns the screen.

Adding Actions in Compat JSON

A menu is declared in the screen section of the compat JSON of the mod that owns the screen — vanilla screens belong to minecraft. Two steps: make sure the key fires on that screen, then attach a menus array to that screen entry. 

{
  "mod_id": "examplemod",
  "mod_versions": [
    {
      "version": "",
      "screenKeys": {
        "key.examplemod.sort": {
          "addToScreens": [
            "net.minecraft.client.gui.screens.inventory.*InventoryScreen"
          ]
        }
      },
      "screen": {
        "com.examplemod.client.gui.ExampleChestScreen": {
          "menus": [
            {
              "id": 1,
              "name": "Quick Actions",
              "translations": { "zh_cn": "快捷操作" },
              "slots": [
                { "actionId": "examplemod:key.examplemod.sort" },
                { "actionId": "jei:key.jei.showUses" }
              ]
            }
          ]
        }
      }
    }
  ]
}

Menu object fields:

Field Description
id1–5, required. The number is the identity of the open key screen_menu_open_N; duplicate ids keep the last one, out-of-range ids drop the whole menu.
name
translations		Display name; translations maps language codes (zh_cn…), same rules as radial menus. With neither, falls back to a localized "Menu N".
posNine-grid placement: lt lc lb tc cc bc rt rc rb; default cc (center).
heightauto (3–12 rows by content) or a fixed row count 3–12; out-of-range values are clamped.
scale0.5–2.0, snapped to 0.05; default 1.0.
slotsUp to 12 entries of { "actionId": "..." }; array order is the display order; a duplicate action keeps only its first occurrence.
  • The overlay section (including the "*" fallback entry) does not support menus — ones found there are dropped with a warning.
  • Layering: built-in compat config is the base; the user layer config/controlflex/compat/user/<mod_id>.json overrides whole menus by id (a written id replaces that menu, missing ids fall back to built-in). The in-game menu editor saves into that same user file.
  • The same action in several menus is perfectly fine — it is only deduplicated within one menu.

Editing in Settings

  • The per-screen settings page gains a Menu tab: menu list, an editor with drag reorder, name / position / height / scale, and a live preview.
  • A duplicate click answers with a toast instead of silently dropping the slot later.
  • Layer Mapping gains Hide inactive actions: the table lists only the rows that can fire on this screen; Reset still walks the unfiltered set.
