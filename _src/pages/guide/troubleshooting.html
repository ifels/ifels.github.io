Troubleshooting

Something is wrong with the controller. Decide which class it is first — the library did not load, the device was never detected, or the game crashed — then follow the matching page.

30-Second Triage

No Controller at All

Gamepad Selection is empty and no button reacts. Check whether the library loaded first, then whether the device reached SDL.

Library Load Failures →

The Game Crashes on Startup

The crash report mentions gamepadjni or UnsatisfiedLinkError, or Windows says it cannot verify the publisher.

Crashes on Startup →

It Works, but Not Right

Rumble, cursor, key mapping or mod screens — those are not loading failures. Start with Settings and the feature pages.

Common Issues

Find the symptom. The detail button opens the steps; anything not listed here starts with the three cards above.

Symptom Likely cause Detail
Windows says it cannot verify the publisher of gamepadjni.dll, and the controller stops working Smart App Control is blocking an unsigned DLL Open →
The log shows no usable gamepad backend Neither the JNI nor the JNA backend could load Open →
The log has a single Failed to load native library line that names SDL3.dll SAC blocked SDL3, so neither backend can start Open →
UnsatisfiedLinkError without the Application Control wording Architecture mismatch: a 32-bit x86 JVM, or an ARM64 JVM on Windows. The JAR ships x86_64 natives only, so Windows on ARM needs an x64 JVM. Open →
no usable gamepad backend with JNA: ... not on the classpath 1.7.10 (or a launcher with a stripped classpath): there is no JNA to fall back to. Open →
Empty gamepad list, and no gamepad-jni error in the log The library loaded fine; the pad never reached SDL. Usually another program is holding it, the Bluetooth pairing is stale, or the cable is charge-only. Open →
The pad works in Steam, but the game never sees it Steam Input has taken the device over Open →
The game crashes on startup, and the report names gamepadjni A native library failure, or a mod conflict Open →
Buttons work, rumble does not The pad has no rumble motors, is low on battery, or is connected in a mode that drops rumble. Open →
Linux: the pad appears and disappears Permission or udev trouble on /dev/input, or Steam Input claiming the device first. Open →
Android: the game runs but no controller is ever listed The launcher rewrote os.version, or Gamepad Input Mode is Mapped (Virtual Keys) instead of SDL Direct. Open →
Two pointers on screen, or the pointer sits away from where clicks land The launcher's virtual mouse pointer is still visible Open →
A mod's key is bound but does nothing Wrong layer, or no screen / overlay rule for that mod Open →

Platform-specific behaviour is on Platform Support; a wrong loader, Java version or dependency is covered by Minecraft Versions.

What to Include in a Report

  • The [gamepad-jni] lines from logs/latest.log — about 30 lines of context, not a screenshot of the game.
  • Your Windows version, and whether Smart App Control is On, Evaluation or Off.
  • Minecraft version, loader, and the exact Control Flex version.
  • Controller model and how it is connected (USB / Bluetooth / dongle).
  • If you can find it: the CodeIntegrity event. Event Viewer → Applications and Services Logs → Microsoft → Windows → CodeIntegrity → Operational, event ID 3077, which names the blocked file.

Where to check SAC: Windows Security → App & browser control → Smart App Control settings. Only On blocks; Evaluation watches without blocking, and Off means SAC is not what you are hitting.
