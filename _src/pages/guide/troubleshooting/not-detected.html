Controller Not Detected

No gamepad-jni error in the log means the library loaded; the problem is below it — the system does not see the pad, another program took it, or the connection itself is wrong.

First, Does the System See It?

Windows: press Win+R, run joy.cpl, and press a few buttons on the Test tab. If the pad is absent here, no game will see it.

macOS: for a wireless pad, check that Bluetooth in System Settings shows it connected; for USB, look for it under System Information → USB.

Linux: evtest or jstest /dev/input/js0 — the device node must exist and produce events.

Another Program Is Holding It

Steam Input, DS4Windows, BetterJoy and remote play all grab the pad first. Once they do, the game sees virtual keys or a virtual pad, and Control Flex never reaches the real device.

Quit those programs completely (not minimize) and restart the game. In Steam, also turn off Steam Input for that pad under Settings → Controller.

To verify: after closing them, the pad is still visible in joy.cpl / evtest — then it is no longer being held.

The Connection Itself

  • USB: use a data cable — many bundled cables are charge-only. Try another port, and avoid hubs.
  • Bluetooth: remove the pairing in the OS, pair again, then wake the pad with its pairing button.
  • Dongle / battery: replace or charge the battery; put the receiver in a rear USB port, not a front-panel one.

Finally, try the same pad in another game or in the system panel — that rules the hardware itself in or out.

Linux: Permissions and udev

Pads live under /dev/input/event* and /dev/input/js*; your user must be able to read them. Flatpak and Snap launchers add a sandbox layer and need device access on top.

Close Steam, check that your user can read the event device, and confirm the pad shows up in evtest or jstest.

If it still fails, check the group on ls -l /dev/input/js*, or add your user to the input group and log in again.

Android: the Launcher

On Android the launcher decides almost everything: Gamepad Input Mode must be SDL Direct, and os.version must not be rewritten to a plain kernel number.

Both settings are described on Platform Support; quit the game completely after changing them.

Also confirm the launcher has device permission; some ROMs hide it behind an “Nearby devices” toggle.

Still Nothing

Search the log for gamepad-jni and SDL: if loading succeeded and no device appears, you are on the right page; if you see UnsatisfiedLinkError, go back to Library Load Failures.

When reporting, attach the log and system details listed on the overview page.
